# 从空工作台到第一次真实交付

打开「Agent」时，先看两个数字：模型状态和在线执行机数。前者决定助手能否理解问题，后者决定任务能否在保存文件的那台电脑上运行。演示实例里即使模型显示可用、在线执行机为零，对话也能返回固定内容。

## 建好工作现场

1. **配置对话。** 打开「Agent → 主 Agent 模型 → 更改模型」。模型 API 填服务商、模型与密钥，兼容接口还需服务地址；选 Codex 命令行时使用服务端电脑上已登录的 CLI。点「保存并应用」，回对话问一个可核对的问题。保存成功只说明配置已接收。
2. **连接工作的电脑。** 打开「执行者与电脑 → 添加电脑」。在目标机安装工作台，登录所选执行器，使用界面给出的代理启动命令。跨机器时把地址换成该电脑可达的服务地址，使用服务端对应的令牌。检查页面上的电脑名和执行器是否可用。生产和本地端口见[操作手册](../operations.md#执行机代理)。
3. **选择真实目录。** 打开「项目 → 从电脑添加 / 发现项目」。发现列表来自电脑上的会话目录；点「添加」才保存项目。找不到时点「更多文件夹 / 手动绑定」，选电脑，填已有目录的绝对路径。若要建新目录，先创建，再点「添加此文件夹」。
4. **验证归属。** 从左侧选具体项目，在工作区写“本项目本周要交一份变更报告，请先列出还缺哪些输入”。回到同一项目应能找到这次对话。切到「全部」只见汇总待办和执行是正常的。目录所在电脑离线时，先恢复原代理。

## 同一件事，什么时候用哪个入口？

| 当前状况 | 操作 | 留下的记录 |
| --- | --- | --- |
| 需求还在讨论 | 在项目工作区发目标，等助手提问再补充。 | 项目对话和上下文 |
| 已经答应交付 | 在项目「待办」输入标题，编辑截止时间、优先级和备注。复杂事项可设上级和前置子项。 | 可跟踪的承诺 |
| 能说清产物，需要电脑执行 | 从关联待办派单；手动任务写完成条件、预计分钟，核对执行器、项目目录和任务原文。 | 待确认的派发内容及本次执行 |
| 在等人选方案 | 回到原问题卡，先看背景，再回答；多卡并存时核对卡号和版本。 | 对应会话采用的决定 |
| 执行者说已做好 | 在执行详情看结果与时间线，对照待办标准打开文件或核对回执。 | 接受当前交付，或登记缺陷返工 |

**看现场时先观察。** 项目「执行」把目录下的现场终端和历史会话列在一起，工作台派发记录在下方。要看正在发生什么，打开现场；要给原终端输入，再显式接管。历史线程需继续时，先核实原终端已停止，再按恢复向导核对电脑、目录、线程、目标和验收条件。每次恢复都会产生新的执行尝试。

**结果未知时保留现场。** 项目目标发送遇到断网或 502，切回原项目后即使「发送目标」还能点，也先看原对话和执行记录。此次浏览器走查复现了“显示发送结果未知，但按钮仍可点”的情况。现有证据只说明按钮状态，不足以断定产生了重复派发。

## 让验收结果在下周仍有用

例：要求“周报逐项附提交标识，缺验证依据的单列”。首次交付漏了两项，就在待办「答复与验收」注明两项缺陷。下一轮看新版本；若承诺包含通知同事，再到发件箱核对送达。最后确认待办完成。把值得以后复用的验收口径放进「工作指令」，自动提炼的经验在「项目设置 → 项目经验」核对。
