# 把每日跟进、定时工作和记忆用起来

第一次交付后，看看哪些步骤每天都在重复。常见的三种需求分别是：提醒我处理积压、到点准备一份产物、下次继续采用已经确认的约定。它们有不同的入口和验收方式。

## 少漏事：先设简报，再决定是否放宽审批

1. 在「Agent → 自动跟进 → 简报与离场通知设置」设时区和早晚时间。在「今日简报 → 查看简报」核对当前待办、已结束执行和待决定项。只想看某个项目时，进该项目的跟进设置。
2. 需要离开 Web 后在飞书收到通知，再配对机器人并启用「离开页面后通知结果和待决定」。如果一条消息没来，检查 Web 是否仍在场、免打扰时段、已保留的通知和待路由数量。
3. 「调整节奏」可改检查间隔、等待提醒时长和停滞阈值。建议先沿用保守策略，看实际是哪类提问打断工作。切「平衡」适合让助手回答普通提问。「少打扰」会放宽受信目录内的权限请求，确认目录及可能的文件改动后再选。

## 每周重复交付：用定时工作

在「Agent → 定时工作 → 从模板创建」选「周报草稿」。核对当地时区、周几、触发时间、执行者、目标和验收标准，再提交创建审批。也有会前准备、执行巡检、下班前盘点模板。

想知道配置是否生效，分三次检查：创建后看「接下来的定时工作」；到点后看是否出现本次派发审批；批准后看执行结果和产物。批准周期配置只建立时间安排。假期可以跳过下一次，项目结束时设置结束时间或暂停；已生成的审批仍需单独处理。

## 把资料变成下一次工作的依据

| 手里的内容 | 怎么存 | 怎么查 |
| --- | --- | --- |
| 我的习惯或偏好 | 「记忆 → 个人」记一条清晰偏好。 | 到个人层打开该条目。 |
| 跨项目通用工作原则 | 选「全局」，写适用条件。 | 后续对话询问当前工作原则。 |
| 某仓库特有的术语或验收口径 | 资料存项目层；每次派活都要遵守的要求写入项目「工作指令」。 | 在项目对话追问本轮用了哪版指令。 |
| 一项已确认的取舍 | 点「新增工作决定」，核对范围并保存。决定改变后修改或撤回。 | 查看当前生效版本，再继续对话。 |
| 会议纪要和受保护文档 | 在「记忆 → 设置与队列」选在线电脑和整理执行者。单独开启受保护来源读取，并核对账号有原文权限。 | 队列看状态和失败原因。纪要助手进入的未分配会议资料，整理后到个人层看。 |

**例：从会议决定追到交付。** 打开「会议日回顾」，选日期和时区，定位当天已登记的会议资料。回到知识页，选中行动项原文，点「将正文选中行加入待办」并确认。下次选同一行点「查看选中行的待办进度」，可以核对登记期限和验收状态。会议中说“周五前完成”是约定；要判断是否完成，仍应打开待办核对。

**希望持续订阅一个来源时**，打开「记忆 → 来源订阅」，选 GitHub 版本发布或仓库状态，填仓库后预览，选择新内容进入记忆或收件箱，再建订阅。需要行动的更新送收件箱，供日后检索的背景资料送记忆。
