# Super Mario 用户 Wiki

**日常工作从「项目 → 工作区」开始。** 在这里说目标、补背景、追问上次做到哪里。需要记住一项承诺时建待办；需要某台电脑产出文件或结果时再派执行。回来后，打开同一项待办核对交付。这条路径把聊天里的一句话变成下次能找到、能继续、能验收的工作。

## 我现在从哪里进？

| 你手里的事 | 第一站 | 到哪里算结束 |
| --- | --- | --- |
| “今天哪些事等我决定？” | Web 主对话，或已配对的全局飞书机器人私聊 | 拿到具体项目或待办，选定下一步 |
| “接着做昨天那个项目” | 对应项目的工作区，或绑定该项目的机器人 | 本轮问题得到回答；需要跟踪的承诺有待办 |
| “有人发来一条需要处理的消息” | 收件箱，打开原消息，核对所属项目 | 按意图留下待办、派发、回复或结论 |
| “我答应周五交一份报告” | 项目里的待办；也可按 `c` 快速添加 | 报告满足约定，由你确认完成 |
| “那台电脑上的任务怎么了？” | 项目里的执行详情 | 从时间线和结果找到本次执行的证据 |
| “对方收到答复了吗？” | 发件箱，核对对应出站记录 | 确认渠道送达状态；需要对方表态时另等答复 |

## 一张图看懂一次交付

下面沿用字符画，直接在终端也能读。箭头表示用户可以走的下一步。咨询、回信和记结论都可以就地结束。

```text
主对话 / 飞书私聊                 项目工作区
        |                            |
        +---- 选定事项与项目 ---------+
                                     |
收件箱原消息 -- 建待办建议并确认 --> 项目待办 <--- 手工登记
                                     |
                         需要电脑产出？--- 否 --> 人工处理
                                     |               |
                                     是              |
                                     v               |
                           核对派发内容并批准         |
                                     |               |
                                一次执行             |
                                     |               |
                               结果与产物             |
                                     v               v
                                 待办「答复与验收」
                                     |
                         +-----------+-----------+
                         |                       |
                     缺项，写明返工要求       满足条件，确认完成
```

**项目决定在哪儿做，待办记你答应交什么，执行记录一次尝试。** 一个项目能长期继续，一个待办可能经过多轮执行。查“上次改了什么”看执行结果；查“我们还欠什么”看待办。项目看板方便排先后，拖动卡片不会验收交付。

## 第一次用：先走一遍最短路径

1. 在仓库根目录用 Node.js 24.9+ 安装依赖。用下面的命令启动隔离演示。打开终端输出的开发地址。临时目录保存本次数据，按 Ctrl+C 退出。

   ```bash
   npm install
   demo_dir=$(mktemp -d)
   npm run dev -- --demo --port 0 --data-dir "$demo_dir"
   ```

2. 打开「项目 → 全部 → 待办」，添加“核对周报是否包含未验证项”。打开详情，写清你打算检查的内容。返回列表再打开它，确认能找回这项承诺。
3. 去首页展开动态图解，熟悉派发和确认的位置。演示使用模拟执行。第一次做真实项目时，在「Agent」核对模型配置、执行机在线状态和可用执行器。进入「项目 → 电脑上的项目文件夹」，选机器和目录，点「添加」。已有目录未出现在候选中时，可用「更多文件夹 / 手动绑定」。[模型和执行机配置](../operations.md#模型与访问配置)
4. 进入项目工作区，先问一个能核对的问题，例如“列出本项目未完成的待办及登记期限”。核对返回的项目和条目后，再尝试派活。接入飞书可延后，Web 可以独立使用。

## 跟做：交付一份本周变更报告

假设周四收到消息：“明天下午给我本周变更，以及哪些还没验证。”以下是操作示例，文件名和时间均可替换。

1. **把要求留在原处。** 在收件箱打开消息，归入对应项目。选择待办建议，把标题改成“周五 15:00 前交付本周变更报告”。确认当前版本后，打开关联待办核对项目、期限和原始要求。自己主动发起时直接建待办即可。
2. **在工作区澄清口径。** 例如问“本周按北京时间从周一算起。哪些修改已有测试记录？哪些还缺证据？”把约定范围写回待办。以后每周都适用的口径，可以保存到项目「工作指令」。
3. **从待办发起关联执行。** 选择项目电脑和执行器。任务写“根据本周提交和已有测试记录，生成 weekly-change.md”。完成条件写“每项变更列出提交标识；验证记录标明来源；缺证据的项目单列”。预计时长可填 10 分钟，供督办参考。批准前检查目录、任务原文和完成条件。如果有人改过预览，重新读最新版。
4. **回来看交付。** 打开执行详情的「结果」，然后打开实际文件，抽查一条提交和一条验证记录。只有“报告已生成”的输出时，要求补文件位置和依据；缺项时在验收处写具体缺陷，例如“第 3 项缺验证来源，请补记录或移入未验证清单”。
5. **兑现原承诺。** 若承诺包含发给请求人，先核对回复对象和正文，再批准发送。需要渠道送达凭据时，在「答复与验收」使用出站回执，核对状态为 `sent`。核对报告和约定的答复后确认完成。下周回看时，从原消息可追到待办，再看对应执行。

## 中途卡住时查哪条记录？

| 看到的现象 | 下一步 |
| --- | --- |
| 收件已归档，事情还悬着 | 打开原消息的关联待办。归档只说明收件处理过。 |
| 已批准派发，迟迟没结果 | 看执行详情的时间线、所绑定电脑和执行器状态。电脑离线时先恢复原机连接。 |
| 派发或发送显示 `unknown` | 记录执行 ID 或出站记录，到原电脑或原渠道核对是否已发生，再决定如何继续。直接重发可能产生第二份交付。 |
| 执行已结束，待办仍开放 | 看当前轮次的结果、文件和验收条件。满足条件后在待办确认；缺证据就记下缺项。 |
| 主对话能查到，项目机器人查不到 | 核对项目归属和机器人绑定范围。用待办 ID 和项目名定位同名事项。 |

## 建议的日常节奏

**早上挑工作**：在主对话问“今天哪些到期，哪些等我决定？”挑一项进入所属项目。**白天留证据**：讨论在工作区继续，承诺记在待办，机器产物关联到本次执行。**收工前验收**：先看已交付且等你确认的事项，再看逾期和结果未知的记录。待办上留下下一步以及在等谁，第二天就能继续。

反复遇到同一问题时再整理记忆。个人偏好放个人记忆，跨项目都适用的工作原则放全局记忆，某个仓库的约定放项目。项目验收后可在「项目设置 → 项目经验」核对提炼结果；某条经验适用于下一次派活，当前这一次仍要看实际交付。
