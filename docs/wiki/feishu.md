# 把飞书接进工作台

先决定要解决哪件事。如果是“出门也能问项目进度”，只接机器人就够了。如果是“同事私聊我的需求容易漏”，接个人消息采集。两者可以分别验证。

```text
我私聊机器人 → 机器人核对主人和范围 → 主助手或项目助手 → 回到原对话
同事发给我   → 已授权的个人账号采集 → 收件箱 → 分拣、转待办或拟回复
已确认的外发 → 对应渠道尝试投递     → 发件箱 → 查实际回执
```

## 先让一个机器人回答项目问题

1. 准备一个已绑定目录的项目，在 Web 为它登记一条容易辨认的待办，例如“核对演示周报”。这条记录用来检查机器人是否看到了正确的项目。需要模型回答时先配好主模型。演示模式适合熟悉界面，真实配对要在正常实例上做。
2. 需要跨项目查询时，从「Agent → 主 Agent 的飞书机器人 → 配置机器人」进入。只想处理一个项目时，从项目的机器人入口进入，也可在「渠道」创建后绑定。首次使用建议从一个项目开始，容易核对范围。
3. 核对机器人名称，点「生成二维码」，用手机飞书扫码。按向导完成确认，等待工作台回读创建和发布状态。如果列出缺失步骤，按该步骤的「前往飞书配置」进入对应应用。确认飞书端版本已发布后，再点「已发布，启用连接」。
4. 在飞书打开**这个机器人**的私聊。界面显示短期配对码时，把码发到私聊。若扫码身份已经核验，直接私聊即可。返回 Web，分别检查机器人显示「已连接」和「已配对」。
5. 在「选择它负责的项目」核对选择，点「绑定」。主机器人应显示「全局（所有项目）」。项目机器人应显示具体项目名。
6. 在原私聊问“本项目有哪些未完成待办？列出标题。”核对之前登记的事项。回 Web「消息 → 进行中」找这次独立对话。只收到一句通用问候，还不能证明项目范围正确。

**已有应用**可在「渠道 → 高级：手动接入、信箱与事件」填写应用标识与密钥，设置工作范围并启用连接，再走私聊配对。遇到创建结果未知，先用页面的日志 ID 和诊断步骤在飞书后台核对已有应用；重复创建会让你难以判断配对的是哪一个。

## 让发给我的消息进入收件箱

1. 打开「渠道 → 飞书 CLI 个人消息采集 → 授权飞书账号」。在采集面板发起授权，用手机扫码确认，或打开面板给出的授权链接。
2. 等面板显示飞书账号。核对账号后点「开启采集」。能看到「停止采集」表示开关已生效。服务端需要可用的 `lark-cli`；页面提示缺少应用时先完成应用接入。
3. 用一条时间和内容都能辨认的普通私聊验收。等下一批采集，点「查看采集消息 → 收件箱」，选「私聊」，打开详情。比对原文；有位置记录时，点「打开原消息」核对会话。需要持续处理时归项目，再转待办。
4. 想停止时，在个人消息采集面板点「停止采集」。仍可回收件箱查看已入箱记录。

| 页面现象 | 怎样查 |
| --- | --- |
| 能私聊机器人，收件箱却是空的 | 查看个人账号是否授权、是否点过「开启采集」。机器人长连接与个人采集各有开关。 |
| 扫码后提示权限不足 | 按面板给出的**当前应用**权限链接处理，然后回来点「重新授权」。 |
| 私聊来了，某个群没有 | 看「私聊最近读到」「最近完整读到」和当前窗口。首次最多取最近 24 小时，私聊优先；普通群受最近活跃范围和免打扰状态限制。 |
| 每批显示 0 条 | 对照消息时间和采集水位。0 只说明本批没有可入箱消息。 |
| 手机确认了，Web 仍未配对 | 看机器人是否启用、长连接是否建立，再核对私聊对象和当前配对码。群聊不能完成主人配对。 |

## 网页版网关、群协作和发件怎么选

- **已有兼容网关，只收私聊**：在「渠道 → 飞书网页版网关 → 配置网关」填写地址和网关签发的令牌。同机默认地址是 `http://127.0.0.1:4310`，远端用 HTTPS。启用插件，扫码登录，确认网关已开启监听，再查最近入箱时间。后台约每 15 秒读一次快照。需要采集群聊时选 CLI；同一账号优先启用一种来源，避免重复。
- **在普通群里处理项目任务**：先完成主人私聊配对，再到「渠道 → 高级」编辑机器人，配置允许的群和成员。在已配置群内明确 @ 对应机器人，用一个能核对的项目问题测试。若要集中调度多个项目，另见[飞书总指挥群](../operations.md#飞书总指挥群)。
- **需要主动通知别人**：先核对发送身份、接收会话、正文和版本，再批准。到「发件箱」查对应记录。待确认说明仍是草稿；结果未知时先到目标会话核实。渠道送达也不能证明对方读过或同意。
- **需要机器人之间协作**：在高级区配置双方授权和范围，选择来源与目标机器人，提交协作请求。到事件信箱看处理与回报。仅需同一个人跨设备接着聊时，一个已配对机器人就够了。
