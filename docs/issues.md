## 六、前端重写（2026-11-16）

用户反馈：已有前端“太丑、不正常、逻辑乱”。用无头浏览器逐页核对后，确认问题在结构上而不是个别样式：

- 标签页和按钮同一种实心紫色，分不出当前项；“全部项目”长得像按钮；作用标签是满屏的胶囊。
- 状态与逻辑缠在一起：元素 id 互相牵连、一行里塞多段逻辑、每个页面各写一套刷新/草稿处理，数据更新会冲掉正在输入的内容。
- 服务端静态资源是手写白名单，每加一个文件都要登记。
- 系统提醒消息把原始 JSON 直接显示给用户。

### F-01 [x] 前端整体重写

- **做法**：重新搭建设计系统（令牌、布局、组件）和模块结构：`lib`（接口、实时数据仓库、路由、提醒点、项目范围）→ `ui`（组件）→ `features`（功能块）→ `pages`（五个页面只做组装）。数据只有一个来源（`store`），列表只重绘变化的行，表单不会被刷新冲掉。
- **一并修掉的缺陷**：选项卡和面板重复 `id`；预设把不可用的方案也标成选中；进入项目时顶栏范围与所看项目不一致；系统提醒显示原始 JSON；静态资源改为按目录安全提供（拒绝越界、隐藏文件、未知类型）；图标改为 DOM 构造，不再拼 HTML 字符串。
- **补回的功能**：任务计划的确认与历史、审批“改一下”（含冲突提示）。
- **保留**：终端观察、机器人信箱、插件文件、后台事件等自成体系的模块放在 `js/legacy/`，由新页面按需挂载。
