# 前端交互重设计方案（第二版）

更新日期：2026-11-16。

状态：**2026-11-16 已按本文重写前端实现**（整体重写，不是在原有实现上修补）。本版取代同日第一版（六个入口加数字角标）。对应问题清单 `issues.md` 第五节与第六节；模块结构见 `code-map.md`；验证见 `tests/web-ui-browser.spec.ts`（17 条浏览器流程）和 `tests/web-lib.test.ts`。

最新用户修正：项目对应电脑上的真实文件夹，默认进入持续工作区对话。进入项目页自动发现目录，显式导入后绑定电脑与目录；旧的“新建名称和目标”流程由目录导入取代。待办、执行、资料、跟进仍保留，具体行为以 `operations.md` 的“项目与记忆”为准。

重写后与本文设计的差异（均为有意取舍）：

- 作用说明：导航每项带一行作用文字；页面和卡片的作用一句话写在标题下，右上角是 ⓘ，点开或悬停看说明和例子（不再是满屏的灰色胶囊）。
- 键盘：只做 `/`、`c`、`g` 加字母、`?`、`Esc`；不做 `j/k` 选中和按键批准。
- 待办快速输入：不做 `#项目`、`明天` 这类自然语言语法；用日期框代替。
- 不做：批量操作、深色模式、跨设备已读。
- 顶栏项目范围跟随当前所看的项目，在顶栏切换会带动项目页。
- 待启动的任务计划计入“等你处理”（服务端待处理聚合新增 `plan` 类型），执行标签页保留计划历史。
- 审批保留“改一下”：保存产生新版本，冲突时提示重新核对。

实现说明：入门引导保留四步全貌，默认先显示下一步操作，其他步骤在聚焦或悬停时展开操作，以满足空状态控件预算。项目跟进字段已持久化，目前仅保存偏好，尚不驱动项目级定时简报或自动处理覆盖。执行时间线只展示已有事实，不补造缺失历史。全局记忆可手动维护，来源整理接口当前只接受个人和项目层。

## 本版相对第一版的修正

用户澄清了两点，第一版理解有误：

1. **“角标”不是数字提醒，而是功能的作用提示。** 每项功能的右上角有一个小标签，说明“这项功能是干什么的”。第一版做成了“待处理数量”，方向错了。数字提醒保留，但降级为次要的“提醒点”。
2. **菜单要少，对话优先，像一个聊天机器人。** 先引导用户做四件事：配置 Agent、跟进项目、添加记忆、连接飞书机器人通道。其余能力收进这几个入口内部，不再平铺成菜单。第一版的六个入口仍然偏多，并且“待你处理”“执行”是按后端模块切的。

3. **底层运行时完全藏在后面。** 终端运行时（Herdr）、SSH、hook、终端宿主这些是实现细节，不影响用户使用，不能有独立菜单，也不能出现在界面文案里。

说明：“Grok bot 形式”指 xAI 那几个个人 Agent 的思路：一个对话入口，加很少的几项配置，没有后台式的功能列表。仓库资料里没有它们的界面，细节我没有对照过，下文按“对话为主、少量入口、首次使用有引导”来设计。如果与实际参照有出入，请指出，第 4、6、7 节会调整。

## 1. 现状与根因

### 1.1 实测数据

用无头浏览器打开演示模式，逐页点击得到：

| 事实 | 数值 |
| --- | --- |
| 侧栏入口 | 13 个，3 组 |
| 首页可见控件 | 56 个；设置 64 个；督办 43 个；知识 42 个 |
| “刷新”按钮 | 11 个页面共 24 个 |
| 去往同一目的地的入口 | 设置 3 个、执行记录 4 个、待办 4 个、知识 3 个 |
| 带提示的入口 | 0 个。没有任何地方说明某项功能是做什么的 |
| 页面总高度 | 设置 4995px、督办 3627px、知识 1704px |
| 不大于 12px 的文字 | 91 处 |
| 开屏动画 | 每次完整加载都出现，要点击或按键才能进入 |

### 1.2 根因

1. **按后端模块切页面，不是按用户要做的事。** 后端有 interactions、approvals、inbox、plans、runs，侧栏就有五个入口。用户要先学会系统怎么拆，才能用。
2. **没有引导。** 新用户看到 13 个入口和一堆空列表，不知道先做什么。
3. **功能不自我说明。** 入口、卡片、表单都没有“这是干什么的”。内部名词（交互卡、督办、分层策略、Herdr 控制台）直接露出。
4. **每页自带一套工具栏。** 刷新、模型配置、使用与架构在每页重复。数据其实已经由 WebSocket 实时推送。

### 1.3 已确认的代码事实

- `app.js` 的 `navigate()` 只切换 `hidden`，不重置滚动。
- `#todos` 被硬编码重定向到 `#inbox`。
- 侧栏数字在 `overview.js` 渲染首页时顺带计算。
- 页面是 `index.html` 中的 14 个 `<section class="panel">`，内容由各 JS 模块填充。
- WebSocket `/api/v1/events` 的消息只触发 100ms 防抖后的 `refresh()`。
- 快照来自 `GET /api/v1/state`。

## 2. 设计原则

| # | 原则 | 违反的表现 |
| --- | --- | --- |
| 0 | **底层不外露。** 终端运行时（Herdr）、SSH、hook、终端宿主、协议这些实现细节不进入菜单和文案；需要用户决定时，用用户的话说明（“这台电脑离线”，不是“终端宿主未注册”）。 | 菜单、标题、按钮、提示中出现 Herdr、SSH、hook、终端宿主、制品、ID 等词 |
| 1 | **对话优先。** 用户首先是“对 Agent 说话”，其他页面是配套。 | 打开应用先看到一堆统计和入口，而不是对话 |
| 2 | **先引导，后罗列。** 新用户一次只看到“下一步”；功能多了也收进入口内部。 | 首屏同时出现 5 个以上平级入口或 15 个以上控件 |
| 3 | **每项功能自带作用说明。** 右上角有作用标签，一眼知道它干什么。 | 出现一个用户说不清用途的入口、卡片或表单 |
| 4 | **等你的事进入对话流，不另开菜单。** | 为审批、提问、待办消息各开一个入口 |
| 5 | **数据自动更新。** | 出现“刷新”按钮 |
| 6 | **不让用户填系统生成的东西。** ID、枚举、路径用选择器。 | 表单有“xx ID”输入框；要手写逗号分隔值 |
| 7 | **同一概念，同一个词。** | 同一对象在不同页面叫法不同 |
| 8 | **高级项折叠，不删除。** 插件、事件、督办节奏等收进“高级”。 | 高级项平铺在主流程里 |
| 9 | **危险操作要明说、可撤销。** | 一次点击就放宽权限 |

## 3. 用户任务与点击预算

| 任务 | 现在要几步 | 目标 | 起点 |
| --- | --- | --- | --- |
| 第一次使用，知道该做什么 | 看 13 个入口自己猜 | 0 步：对话页直接显示 4 步引导 | 打开应用 |
| 打开后知道“有什么在等我” | 看首页磁贴 + 切 3 个页面 | 0 步：对话顶部一条“有 3 件事等你”，展开即处理 | 打开应用 |
| 记一条待办 | 4 步 | 2 步：按 `c`，输入标题回车 | 任意页 |
| 对 Agent 说一句话 | 首页输入后跳转，发送按钮可能在首屏外 | 1 步：回车 | 对话 |
| 批准一个动作 | 找“审批”页，首先是创建表单 | 1 步：在对话里点“批准” | 对话 |
| 回答 Agent 的提问 | 去“交互卡”页 | 1 步：在对话里输入回答回车 | 对话 |
| 看某个项目的进展 | 在待办、执行记录、任务计划三处找 | 2 步：点“项目”→点项目，待办、执行、资料在同一页 | 项目 |
| 看某个任务的终端 | 另一个入口 | 3 步：项目 → 任务 → “终端”标签 | 项目 |
| 让 Agent 记住一件事 | 展开折叠区后填表 | 2 步：点“记忆”，输入框里写一句回车 | 记忆 |
| 连接飞书机器人 | 在设置长页里找 | 3 步：点“渠道”→扫码→在飞书里发配对码 | 渠道 |
| 换模型 | 每页都有按钮，位置不固定 | 2 步：点“Agent”→模型卡 | Agent |
| 改自动处理规则 | 手写顺序、填 ID | 3 步：Agent → 自动处理 → 选预设 | Agent |

## 4. 信息架构：对话 + 4 个入口

### 4.1 新导航

```
对话        主页。与 Agent 说话；等你处理的事也出现在这里
Agent       配置 Agent：模型、执行者与电脑、自动处理规则
项目        跟进项目：每个项目的待办、执行、资料
记忆        个人 / 全局 / 项目记忆
渠道        飞书机器人通道
```

5 个入口，不分组，没有“设置”。顺序对应使用顺序：先对话，再配置 Agent，再建项目，再加记忆，再接渠道。

不做的入口：收件箱、交互卡、审批、执行记录、任务计划、终端、督办与简报、分层策略、插件与连接、首页。它们的内容并入上面五个入口，见 4.2。

### 4.2 旧功能去了哪里

| 旧入口 | 去向 | 怎么呈现 |
| --- | --- | --- |
| 首页 | 对话 | 对话页的空状态是引导；有内容后是对话 |
| 收件箱（待人决策、待 AI 执行） | 对话顶部“等你处理” + 项目的“待办”标签 | 来自飞书的消息带“飞书”来源标记 |
| 交互卡 | 对话（提问卡） | 卡片出现在对话流里，回答后收起 |
| 审批 | 对话（审批卡） | 同上。创建动作表单移到项目 → 执行 → “发起执行” |
| 待办 | 项目的“待办”标签；对话里按 `c` 快速添加 | 没有项目的待办在“全部”下 |
| 执行记录、任务计划 | 项目的“执行”标签（计划作为分组） | |
| Herdr 控制台 | 项目 → 某个任务 → “终端”标签；电脑列表在 Agent 页 | |
| 项目 | 项目 | 保留，成为主要工作区 |
| 知识 | 记忆 | 改名，用户更容易理解 |
| 督办与简报 | Agent → 自动跟进（折叠在高级前） | |
| 分层策略 | Agent → 自动处理 | |
| 插件与连接 | 插件在 Agent → 高级；飞书在渠道 | |
| 模型配置 | Agent → 模型 | 不再每页出现 |

### 4.3 旧地址重定向

旧地址全部保留，书签不失效。新地址格式 `#页面` 或 `#页面/子页`，标签页和选中的项目也写进地址。

| 旧地址 | 新位置 |
| --- | --- |
| `#overview`、`#chat` | `#chat` |
| `#inbox`、`#interactions`、`#approvals` | `#chat`，并展开“等你处理” |
| `#todos` | `#projects/all/todos` |
| `#runs`、`#plans`、`#terminals` | `#projects/all/runs` |
| `#projects` | `#projects` |
| `#knowledge` | `#memory` |
| `#supervision` | `#agent/follow-up` |
| `#policies` | `#agent/rules` |
| `#settings` | 有飞书异常时 `#channels`，否则 `#agent` |

### 4.4 概念对齐：界面上的名词

| 用户看到的 | 系统对象 |
| --- | --- |
| 待办 | `Todo` |
| 提问 | `Interaction` |
| 审批 | `Approval` / 权限卡 |

## 5. 作用标签（右上角标）

这是用户明确提出的要求：每项功能右上角有标签，说明它的作用。

### 5.1 规则

| 项 | 规则 |
| --- | --- |
| 位置 | 每个功能块的右上角：页面标题栏、每张卡片、每个抽屉 |
| 形态 | 灰色小胶囊：`ⓘ 一句话作用`。不超过 12 个汉字。例如 `ⓘ 让 Agent 记住你` |
| 展开 | 悬停、聚焦或点击展开气泡：两句话说明作用 + 一个例子 + “了解更多”（可选） |
| 导航项 | 侧栏每项两行：名称 + 不超过 10 个汉字的作用，如“记忆 / 让 Agent 记住你”。窄屏底栏只显示名称，作用放在长按提示里 |
| 是否可关闭 | 用户可以在“高级 → 界面”里一键关闭全部标签；也可以对单个标签点 `×` 关闭，本机记住 |
| 不重复 | 同一页面里，标题栏已有标签时，内部卡片不重复写相同含义 |
| 无障碍 | 标签文字就是读屏文字；气泡内容用 `aria-describedby` 关联 |
| 来源 | 文案全部来自 `hints` 文案表（见 5.3），页面代码不写死 |

### 5.2 每个功能的标签

导航与页面：

| 功能 | 标签（≤12 字） | 展开说明 | 例子 |
| --- | --- | --- | --- |
| 对话 | 说出目标，Agent 来办 | 你只需要说想做什么。Agent 会结合记忆选择执行者，并把结果带回来。 | “把登录页的报错修一下” |
| Agent | 配置谁来干活 | 设置主 Agent 用的模型，接入 Claude Code、Codex 等执行者，并决定哪些事可以自动处理。 | 选模型、添加一台电脑 |
| 项目 | 让 Agent 持续跟进 | 一个项目聚合它的待办、执行和资料。Agent 会按设定的节奏跟进，逾期会提醒你。 | “官网改版” |
| 记忆 | 让 Agent 记住你 | 保存你的偏好、工作原则和项目资料。Agent 每次工作前会参考，并说明用了哪几条。 | “先给结论，再给依据” |
| 渠道 | 在飞书里找 Agent | 把飞书机器人接进来后，可以在飞书里对话，别人发给你的消息也能变成待办。 | 在飞书里发“今天有什么要处理” |

卡片与区块：

| 位置 | 标签 | 说明 |
| --- | --- | --- |
| 对话顶部“等你处理” | 需要你拍板的事 | 审批、提问、飞书消息待办集中在这里，处理完自动收起。 |
| Agent → 主 Agent 模型 | 对话用的大脑 | 主 Agent 回答你、拆解任务时使用的模型。 |
| Agent → 执行者与电脑 | 真正动手的人 | 执行者在你的电脑上运行命令行 Agent。这里管理有哪些电脑、哪些在线。 |
| Agent → 自动处理 | 哪些事不用问你 | 决定提问和审批由谁先处理，多久还没人理再交给你。默认全部交给你。 |
| Agent → 自动跟进 | 到点提醒与简报 | 设置简报时间和逾期提醒。 |
| Agent → 高级 | 插件与排查 | 通常不用动：插件、事件、发件箱、使用导览。 |
| 项目 → 待办 | 这个项目要做的事 | 你自己记的，或从飞书消息转来的。 |
| 项目 → 执行 | Agent 做过的事 | 每次派给执行者的任务、状态和结果。 |
| 项目 → 资料 | 这个项目的记忆 | 只对这个项目生效的背景和文档。 |
| 项目 → 跟进设置 | Agent 怎么盯这个项目 | 简报时间、逾期提醒、自动处理的覆盖设置。 |
| 记忆 → 个人 | 你自己的事 | 个人安排、生活背景。 |
| 记忆 → 全局 | 通用的工作原则 | 所有项目和事务都适用，不等于公开。 |
| 记忆 → 项目 | 某个项目的背景 | 区分多个项目，互不混用。 |
| 渠道 → 飞书机器人 | 在飞书里和 Agent 对话 | 用机器人身份收发消息。 |
| 渠道 → 个人消息采集 | 把发给你的消息变待办 | 需要单独授权，只读，默认关闭。 |

### 5.3 文案表

标签与说明集中存放在 `apps/web/copy/hints.js`：

```js
export const hints = {
  'nav.chat':     { tag: '说出目标，Agent 来办', detail: '你只需要说想做什么……', example: '“把登录页的报错修一下”' },
  'nav.agent':    { tag: '配置谁来干活', detail: '……' },
  'memory.global':{ tag: '通用的工作原则', detail: '……' },
};
```

页面用 `<span data-hint="memory.global">` 声明，渲染函数统一生成标签与气泡。新增功能必须同时新增文案条目，否则测试失败（见 UX-03）。

### 5.4 提醒点（次要）

数字类提醒降级为“提醒点”，只表示需要你行动，不再承担说明功能的职责：

| 位置 | 样式 | 含义 |
| --- | --- | --- |
| 对话入口 | 红色数字 | 有几件事等你处理（审批、提问、飞书消息待办） |
| 项目入口 | 红点 | 有项目的待办逾期，或有失败的执行 |
| Agent、渠道入口 | 红点 | 模型不可用、电脑离线、飞书断开等 |
| 记忆入口 | 无 | |

规则：为 0 不显示；红色只表示“需要你行动”；浏览器标题用 `(N)` 前缀；数字用同一个纯函数计算（见 12.3）。提醒点画在图标右上角，作用标签在入口名称旁，两者不冲突。

## 6. 首次使用引导

目的：新用户不面对一堆功能，只看到“下一步”。引导就是对话页的空状态，四步，对应四个入口。

```
对话                                                      ⓘ 说出目标，Agent 来办
─────────────────────────────────────────────────────────────────────────
  你好。先花几分钟做好这四件事，之后只需要对我说话。

  ┌ ① 配置 Agent ──────────────────────── ⓘ 配置谁来干活 ┐   ✓ 已完成
  │ 选一个模型，再接入一台能运行 Claude Code 或 Codex 的电脑  │
  │ [去配置]                                                  │
  └───────────────────────────────────────────────────────────┘
  ┌ ② 添加一个要跟进的项目 ─────────────── ⓘ 让 Agent 持续跟进 ┐   ○ 未完成
  │ 给项目起个名字，写一句目标。Agent 会据此跟进待办和执行      │
  │ [新建项目]                                                  │
  └───────────────────────────────────────────────────────────┘
  ┌ ③ 告诉我一些背景 ───────────────────── ⓘ 让 Agent 记住你 ┐   ○ 未完成
  │ 写下你的工作原则或粘贴项目资料。                             │
  │ [添加记忆]                                                  │
  └───────────────────────────────────────────────────────────┘
  ┌ ④ 连接飞书机器人 ─────────────────── ⓘ 在飞书里找 Agent ┐   ○ 未完成（可跳过）
  │ 之后可以在飞书里和我对话，别人发你的消息也能变成待办。       │
  │ [去连接]  [先跳过]                                          │
  └───────────────────────────────────────────────────────────┘
  ┌─────────────────────────────────────────────────────────────┐
  │ 或者直接说你想做什么…                              [发送 ↑] │
  └─────────────────────────────────────────────────────────────┘
```

**规则**

| 项 | 规则 |
| --- | --- |
| 完成判定 | ① 模型可用且至少有一台在线电脑；② 至少一个项目；③ 至少一条记忆；④ 飞书机器人已连接或已选择“先跳过”。状态由服务端快照判定（12.2 的 `setup`），不靠本地记忆 |
| 展示 | 只显示未完成的步骤，已完成的折叠为一行“✓ 已完成 3/4”。全部完成或跳过后，引导消失，不再出现 |
| 可以不做 | 任何一步都不是使用的前提：用户可以直接在输入框说话。没有模型时，发送按钮禁用并说明原因 |
| 回到引导 | Agent → 高级 → “重新查看引导” |
| 演示模式 | 引导照常显示，每步旁标注“演示数据” |

### 7.3 Agent（配置 Agent）

**目的**：让 Agent 能工作，并决定它能自己做多少。一页，三张卡 + 折叠的高级，不分标签页，高度不超过一屏半。

```
Agent                                                     ⓘ 配置谁来干活
┌ 主 Agent 模型 ─────────────────────────────── ⓘ 对话用的大脑 ┐
│ ● 可用   来源：Codex 命令行 · 模型：default                     │
│ [更改模型]                                                      │
└───────────────────────────────────────────────────────────────┘
┌ 执行者与电脑 ─────────────────────────── ⓘ 真正动手的人 ┐
│ 电脑 A   ● 在线   Claude Code ✓  Codex ✓        [详情]         │
│ 电脑 B   ○ 离线   上次在线 2 小时前                [详情]         │
│ [＋ 添加电脑]                                                   │
└───────────────────────────────────────────────────────────────┘
┌ 自动处理 ───────────────────────────────── ⓘ 哪些事不用问你 ┐
│ 当前：保守（审批都交给你；提问先由 Agent 给建议）               │
│ ( ) 保守   ( ) 平衡   ( ) 少打扰                               │
│ 自定义规则（2）▸                                                │
└───────────────────────────────────────────────────────────────┘
┌ 自动跟进 ───────────────────────────────── ⓘ 到点提醒与简报 ┐
│ 每天 09:00 发简报 · 逾期待办提醒：开                            │
└───────────────────────────────────────────────────────────────┘
▸ 高级（插件、事件与发件箱、使用导览、开屏预览、导入导出）
```

**模型卡**

- 更改模型在抽屉里完成：来源（模型 API / Codex 命令行）、供应商、模型、密钥；`测试连接` 按钮；保存后立即显示结果。不再是每页都有的对话框。

**执行者与电脑卡**

- 每台电脑一行：名称、在线状态、已有的执行者。点“详情”进入抽屉，显示能力、路径、插件文件确认状态。
- “添加电脑”抽屉：给出一条安装命令和配对码，电脑连上后在此确认归属。取代原“制品与执行机”区。
- 状态异常时整张卡顶部出红条，说明原因和处理办法。

**自动处理卡**

- 三个预设：保守（默认）、平衡、少打扰。选择前显示与当前配置的差异。
- 预设对应：

  | 预设 | 含义 |
  | --- | --- |
  | 保守 | 审批和计划审批都交给你；Agent 只回答普通提问并仅给建议 |
  | 平衡 | 在“已信任目录”内的只读操作自动批准；普通提问由督办 Agent 直接回答 |
  | 少打扰 | 常见开发操作自动批准；提问先由 Agent 回答，3 分钟无结果再问你。放宽审批，选择时弹出确认 |

- “自定义规则”展开后是一句话规则列表：

  ```
  当 [Agent 提问 ▾] 来自 [项目：官网改版 ▾] 时，
  由 [督办 Agent ▾] [直接回答 ▾]，[3] 分钟没人处理交给 [你 ▾]       [停用] [删除]
  ```

  范围用项目选择器，不填 ID；放宽审批的规则整行红边并带“高风险”，保存时确认并写明后果；每条规则下一行显示“过去 7 天处理了 N 次”。任务级范围只在执行详情里设置。

**高级**（折叠，默认收起）：插件列表与启停、事件与发件箱、督办节奏细项、整理 Agent 配置、使用导览、开屏预览、关闭作用标签、导入导出原始配置。旧页面里的这些功能全部保留，只是不进主流程。

### 7.4 项目（跟进项目）

**目的**：项目是主要工作区，待办、执行、资料都挂在项目下。

**列表**

```
项目                                                ⓘ 让 Agent 持续跟进   [＋ 新建项目]
 全部（12 待办 · 2 执行中）
 官网改版     逾期 1 · 执行中 1        Agent 每天 09:00 汇报
 后端重构     待办 4 · 执行中 0
 个人事务     待办 3
```

- 左侧或上方是项目列表，第一项“全部”汇总所有项目（含未归类的待办和执行）。
- 项目从电脑上的已有文件夹导入，名称默认取文件夹名；旧项目可补绑目录，已有背景和资料保留。单项目默认进入工作区持续对话，单次执行的验收/预计时长不作为项目创建条件。

**项目详情**（`#projects/<id>/<tab>`）

```
官网改版                                    ⓘ Agent 会持续跟进这个项目
一句话目标：把官网首页改成新品牌样式
 [待办 4] [执行 2] [资料 5] [跟进设置]
 ─────────────────────────────────────────────────────────────
 [ 添加待办：输入标题，回车…                                  ]
 需要你    · 确认设计稿                                        今天
 逾期      · 回复张三评审时间                                  昨天
 等待中    · 等设计师给图                         等 李四
 之后      · 上线检查清单
```

| 标签 | 内容 |
| --- | --- |
| 待办 | 始终可见的“添加待办”输入框；分区：需要你、逾期、今天、等待中、之后、某天、刚完成（分区由服务端统一计算）。来自飞书的待办带“飞书”标记，点开可看原消息 |
| 执行 | 按状态分组，“失败”“结果未知”置顶；计划显示为可展开的分组；右上“发起执行”打开抽屉 |
| 资料 | 本项目的记忆条目（等同记忆页的项目层，按项目过滤） |
| 跟进设置 | 简报时间、逾期提醒、本项目的自动处理覆盖。每项带作用标签 |

**执行详情**（`#projects/<id>/runs/<runId>`）：时间线 / 结果 / 终端三个标签。

- 时间线：派发、状态变化、提问与回答、审批与结果，每条标注来源。
- 结果：最终回复、交付物、退出原因。页面底部单独一行“验收标准……  [标记待办已完成]”，**执行结束不等于待办完成**，由用户点。
- 终端：默认只读；“接管输入”进入控制；断线时顶部黄条说明显示的是最后一帧，恢复后先显示完整画面。
- 状态为“结果未知”：顶部红条“动作已发出但没收到确认，不要重复发起 [核对]”。

**发起执行抽屉**

| 字段 | 控件 |
| --- | --- |
| 要做什么 | 多行输入，必填 |
| 谁来做 | 选择器：自动选择（推荐）/ 具体执行者（显示名称和在线状态，不显示 ID） |
| 目录 | 选择器：执行者常用目录 / 手动输入 |
| 关联待办 | 选择器（可选） |
| 怎样算完成 | 输入。修改类任务必填，示例“npm test 通过，登录页无报错” |
| 预计用时 | 数字，修改类任务必填 |
| 高级（折叠） | 任务或交互会话等 |

## 8. 通用组件

### 8.1 待处理卡（审批、提问、飞书消息待办共用）

```
┌ [类型]  标题（一句人话）                                来源 · 时间 ┐
│  上下文一行：谁、在哪、关联什么                                      │
│  ▸ 详情（折叠）                                                      │
│  [主操作]  [次操作]  [⋯]                                             │
└──────────────────────────────────────────────────────────────────────┘
```

| 部分 | 规则 |
| --- | --- |
| 类型 | 审批（橙）、提问（蓝）、待办（灰）。不是按钮 |
| 标题 | 一句话，动词开头，不出现原始字段名 |
| 详情 | 折叠；原始命令、参数在这里，字段用人话名称 |
| 主操作 | 每种类型一个：批准 / 回答 / 转成待办。`Enter` 触发 |
| 高风险 | 标题前红色“高风险”；主操作需二次确认（“再点一次确认批准”，3 秒内有效） |
| 失败 | 卡片显示红条和“重试”，内容保留 |
| 并发 | 另一设备已处理：卡片显示“已在另一设备处理”，淡出，不报错 |
| 处理后 | 原地变为一行“已批准 · 撤销（10 秒）”。已被执行端接收的动作不提供撤销，显示“已接收，结果见执行” |

### 8.2 状态标签

| 状态 | 文案 | 色 |
| --- | --- | --- |
| queued | 排队中 | 灰 |
| running | 执行中 | 蓝 |
| waiting_input | 等你回答 | 红 |
| waiting_approval | 等你批准 | 红 |
| completed | 已结束 | 绿（不写“成功”，结束不等于完成） |
| failed | 失败 | 红 |
| unknown | 结果未知 | 红，带问号图标 |
| cancelled | 已取消 | 灰 |

### 8.3 空状态

三行：为什么是空的；这里会出现什么；一个动作。不用“暂无记录”。

### 8.4 反馈与撤销

成功原地变化，不弹 toast；可撤销的原地显示“撤销（10 秒）”；失败在发生处显示红条并保留输入；全局错误是页面顶部一条带“重试”的提示条。只有连接状态变化使用 toast。

### 8.5 表单

必填写在标签旁；系统生成的值不填，用选择器；长表单分组折叠；提交按钮用动词（“保存规则”“开始执行”）；失焦校验，提交时焦点移到第一个错误。

### 8.6 抽屉与对话框

创建、编辑用右侧抽屉（480px，窄屏全屏）；只有破坏性确认用对话框，正文写后果，按钮用具体动词。

### 8.7 作用标签组件

```
<span class="hint" data-hint="memory.global">ⓘ 通用的工作原则</span>
```

- 渲染函数 `renderHint(key)` 读取文案表，生成标签和气泡。
- 气泡打开时 `Esc` 关闭；失去焦点关闭；窄屏用点击而不是悬停。

## 10. 视觉与动效

### 10.1 字号

| 用途 | 字号 |
| --- | --- |
| 页面标题 | 22px 加粗 |
| 卡片标题 | 15px 加粗 |
| 正文 | 14px |
| 辅助说明、作用标签 | 13px / 12px |
| 提醒点数字 | 11px（唯一例外） |

可读文字不小于 12px。

### 10.2 间距

刻度 4、8、12、16、24、32；卡片内边距 16px、间距 12px；可点击元素桌面最小高 32px、触屏 44px。

### 10.3 色彩语义

红：需要你行动 / 失败 / 危险；橙：审批；蓝：进行中；绿：已连接；灰：次要与作用标签；主色（紫）：主按钮、当前导航、焦点。对比度达 WCAG AA。首版只做浅色，颜色全部走 CSS 变量。

### 10.4 开屏动画

只在首次启动出现一次，不拦截操作，1.5 秒后自动淡出，点击任意处可关闭；之后不再出现；Agent → 高级 可预览；遵守 `prefers-reduced-motion`。

### 10.5 页面切换

切换后滚动到顶；后退时恢复离开时的位置（以地址为键，存在内存中）；无动画，或 ≤ 100ms 淡入。

## 15. 取舍与未决事项

### 15.1 已做的取舍

| 取舍 | 选择 | 理由 |
| --- | --- | --- |
| 入口数量 | 对话 + 4 个，共 5 项 | 用户明确要求不要把一堆东西列出来；其余收进入口内部 |
| 审批、提问、待办消息 | 进对话流，不设入口 | 它们是“Agent 在等你”，天然属于对话 |
| 项目是否是工作区 | 是，待办、执行、资料都挂在项目下 | 与“让 Agent 跟进项目”的定位一致；没有项目的内容归“全部” |
| 作用标签是否可关闭 | 可关闭 | 熟悉后不再需要，避免长期噪音 |
| 数字提醒 | 保留，降级为提醒点 | 仍需要提示“有事等你”，但不再作为“角标”的主义 |
| 设置入口 | 取消，并入 Agent 和渠道 | 避免“设置”变成杂物间 |
| 深色模式 | 不做，只保留变量 | 范围控制 |
| 已读状态 | 本机保存，不跨设备 | 避免为一个红点引入服务端状态 |
| 撤销批准 | 仅在未被执行端接收前 | 已接收的动作无法撤回，不给虚假的安全感 |

### 15.2 已定决策（2026-11-16，用户授权按设计判断执行，不再逐项确认）

| 事项 | 决定 | 理由 |
| --- | --- | --- |
| 入口数量与内容 | 对话 + Agent、项目、记忆、渠道，共 5 项 | 对应用户列出的四件事，其余收进入口内部 |
| “渠道”是否独立入口 | 独立 | 用户把“飞书机器人通道”单列；以后接其他渠道也放这里 |
| 自动处理预设 | 首版提供“保守 / 平衡 / 少打扰”三个；默认“保守”；选择“少打扰”前弹确认，写明会自动批准哪些操作 | 用户要求自动处理可配置；放宽审批的风险靠确认和命中记录控制，不靠不提供 |
| 作用标签 | 默认全部开启；每个标签可点 `×` 关闭，本机记住；“高级”里可一键关闭全部。不做按天数自动隐藏 | 自动隐藏是隐含状态，会让用户困惑“标签去哪了”；手动关闭更可预期 |
| 快捷键 | `/` 搜索、`c` 添加待办、`g` 加字母跳页、`?` 列表、`Esc` 关闭。**不提供“按键直接批准”** | 批准是高风险动作，误触代价大 |
| “Grok bot 形式” | 按“对话优先、很少几项配置、首次有引导”落实 | 用户说明其思路简单；未对照原界面 |
| 已读状态 | 本机保存，不跨设备同步 | 不为一个提醒点引入服务端状态 |
| 文案表 | 作用标签与词表放进代码仓库，随版本更新 | 便于统一审阅和测试 |

开发中遇到本文没有覆盖的问题，按第 2 节原则判断，并把结论补进本节。
