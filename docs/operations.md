# 操作手册

从工作台左下角打开「插件配置」。搜索并选择插件可查看用途、状态、功能和设置。启停影响整个工作台；入口固定位置和 Token 统计的使用偏好保存在当前浏览器。Token 统计支持表单与 JSON，保存后下次打开生效。

打开「用量来源」可配置账户池网关或通用 JSON 接口，试读后保存，按设定间隔刷新。窗口百分比表示该账号在指定时段内已使用的额度。可按提供商控制显示范围。Web 主对话和配对的飞书主人私聊可以查询缓存中的窗口和采样时间。读取失败时请核对来源状态和上次成功时间。

管理网关还提供「网关账户清单」，包含停用、隔离、不可调度及缺少用量读数的账户。清单复用上一次采集结果。重启后需等首次采集；上次读取失败时，清单会标明记录已过期。Web 主对话和配对主人私聊可查询，插件可通过显式声明的 `usage_gateways` 权限调用 `usage.gateway_accounts`。

## 配对另一台浏览器

登录管理员页面后打开「浏览器设备」，也可在持工作台主令牌的浏览器中打开同名入口。为新设备取名并生成配对链接。请在目标浏览器打开链接，或扫描同页的二维码，点击确认后即可进入工作台。链接只能使用一次，有效期为 5 分钟。管理员和持主令牌的浏览器都可以查看设备最近使用时间，并按名称确认撤销指定设备。撤销会断开该设备现有的实时连接，旧凭据随即失效。

在已配对的浏览器打开连接菜单，可以主动断开当前设备。确认后，工作台撤销这台设备的凭据并清除本地登录。若工作台无法确认撤销，可以重试，或选择仅在本地退出。仅本地退出后，旧凭据仍可能有效；同一浏览器保留了替换证明时，下次配对可同时撤销旧设备。主令牌登录也支持仅本地退出。

## 管理员登录

从 Agent 页的高级设置打开管理员页面，也可直接访问 `/admin.html`。首次设置时，在服务端本机使用已通过主令牌连接的浏览器领取设置码。设置码有效期为 10 分钟，重新领取会使旧码失效。若服务端机器没有浏览器，可在该机配置服务使用的 `SUPER_MARIO_TOKEN`，运行 `super-mario admin setup-code --port 48080`，再在管理员页面填写设置码和密码。端口按实际实例填写。未配置主令牌的实例需要先配置令牌，再领取设置码。

以后在该页用管理员密码登录。修改密码需要输入当前密码，成功后其他管理员会话失效。退出只结束当前管理员会话。工作台与执行机继续使用各自的访问凭据。

管理员登录后可在概览查看实例标识、启动时间、监听地址、在线执行机数和配对设备数。显示名称可更改，清空后恢复默认值。直连地址按服务端本机的监听和网卡生成，反向代理的公网地址与外部可达性需要另行核对。「运行诊断」读取当前状态，并显示检查时间和各项结果。服务端诊断不会启动执行机上的 CLI。

在「执行机管理」点击「查看执行机」，可核对每台执行机的 ID、上报名、在线状态、平台、最近连接时间和上报能力。点击「刷新执行机」读取最新状态。「保存显示名」设置管理页使用的别名，「恢复上报名」重新使用执行机自己上报的名称。

要移除已登记的执行机，先停止该机代理，刷新清单，核对离线状态和 ID，再确认移除。移除会清理清单记录、管理页别名和该机专用凭据，保留历史任务。之后若用工作台主令牌启动该机，它会重新登记。

新执行机先运行 `super-mario-agent --print-machine-id` 取得 ID。使用自定义数据目录时，两次启动都传同一 `--data-dir`。管理员按该 ID 签发专用凭据，在执行机上通过 `SUPER_MARIO_TOKEN` 配置凭据，再用 `super-mario-agent --url <服务地址>` 连接。撤销会断开使用这份凭据的连接，并阻止它重连；待加入的执行机也可以撤销。原先用工作台主令牌接入的代理仍按原方式认证。

管理员页面的「插件诊断」列出当前实例已加载和加载失败的插件。可按状态或名称查找，展开后查看版本、来源、功能、宿主 API 权限及依赖状态。显示「等待」时，先核对依赖是否已加载并运行。展开插件可查看最近 1 小时、24 小时或 7 天内宿主记录的服务、包装器和钩子调用。调用数为零表示该窗口内没有已记录的调用。「最近调用」展示当前服务进程中该插件最近 200 次调用的操作名、完成时间、耗时和结果，可按操作名或失败状态筛选。重启后从新进程的第一条记录开始。

### 浏览器密码登录

管理员可在「浏览器密码登录」设置独立的连接密码。另一台浏览器在连接菜单选择「使用浏览器密码登录」，填写设备名称和连接密码。登录成功后，这台浏览器出现在设备列表中，可单独撤销。

停用会阻止后续密码登录。重新启用可沿用已保存的连接密码。修改或停用时，勾选「同时撤销通过密码登录的设备」会使这些设备的旧凭据失效，通过配对链接连接的设备仍可使用。

## 本地开发

需要 Linux 和 Node.js 24.9+。在仓库根目录运行：

```bash
npm install
npm run dev
```

默认打开 `http://localhost:3001`。开发数据保存在 `$XDG_CACHE_HOME/super-mario/dev`，未设置 `XDG_CACHE_HOME` 时使用 `~/.cache/super-mario/dev`。下次启动可继续使用这些数据。

需要一次性验证时，可用临时目录和系统分配的空闲端口，打开启动日志中的地址。以下示例使用演示模式，无需模型密钥、飞书账号或真实执行机。

```bash
dev_data_dir=$(mktemp -d) && npm run dev -- --demo --port 0 --data-dir "$dev_data_dir"
```

开发实例按需启动，调试结束按 Ctrl+C 退出。源码修改会触发开发进程重启，Web 静态文件刷新页面即可。开发模式直接读取源码。

## 订阅公开仓库的版本更新

在「记忆」打开「来源订阅」，选择「GitHub 版本发布」，填写公开仓库的 `owner/repo`。点「预览来源」可先看标题、说明和原文链接。预览只读取首页。订阅每页最多读取 30 个版本，包含预发布版本。还有下一页时，工作台会在下次调度继续，也可以点「立即拉取」读取下一页。服务重启后从已保存的页继续。整轮完成后，后续拉取从最新版本读到上轮的起始版本，按发布编号去重。来源重复返回同一续页标识，或第 100 页仍有后续页时，订阅会暂停并显示原因。

填写订阅名称和拉取间隔，勾选「收件箱」「个人记忆」中的一个或两个位置。创建后可等到下个周期，或点「立即拉取」。工作台运行时每 30 秒检查一次到期订阅。如果部分投递失败，可在目的地恢复后再次拉取。已成功的目的地保留原内容。同一来源插件的资源共用限流等待时间。连接器返回等待时长时，工作台按该时长暂停远程读取；未提供时等待一分钟。重启或切换订阅开关会保留等待时间。等待期间仍可手动补投上次已经读到的条目。展开「来源关系图」可按去向或异常状态筛选，再点订阅名称查看设置。

在 Web 主对话或已配对主人的飞书主机器人私聊里，可以问“我订阅了哪些仓库，分别送到哪里？”或“预览一下这条订阅”。助手读取当前配置或来源摘录。预览不会触发投递。也可以告诉助手仓库、投递位置和频率，请它拟订阅草案。在「记忆」的「来源订阅」按编号打开草案，核对后点「创建订阅」。草案保留七天，可使用一次。

条目订阅默认将同一来源话题的更新合进一张收件卡，没有话题编号时各自入箱。选「整条订阅使用一张卡」可合并后续更新。新卡片会从最近八天的已收件记录中取同话题的上下文，最多列十条早期记录和最新正文。「本次收录」按这次送达的条目计数。开启收件箱时，系统补收此前 24 小时内已观察的条目，并核对首轮读取结果。首次读取有多页时，个人记忆按页投递；收件箱在最后一页读完后归并整轮结果。中途可在订阅行查看暂存数量和下次读取的页序。普通积压超过三条时生成摘要。单份摘要最多归并五百条，显示前五十条及其余数量。开启后首次拉取时仍有未来截止时间的事项按正常话题展示。个人记忆仍逐条保存。

投递到收件箱时，可在订阅里填写分拣规则，例如「只有不兼容更新需要处理」。留空时沿用来源插件提供的规则。模型暂时无法分类时，默认把有结构化截止时间的条目标为「需要处理」，其余标为「知会」。也可以统一指定等级，或选择「等待模型分拣」。等待中的条目已经入箱，模型恢复后继续分拣。可在收件箱按「等待模型分拣」筛选。这些设置不会自动创建待办。

点「编辑订阅」可调整名称、间隔和目的地。点「删除订阅」并确认后，系统清除这条订阅的待投递内容，保留已投递的收件记录和个人记忆。

要跟踪仓库设置，在「来源订阅」选择「GitHub 仓库状态」。它比较仓库名、描述、默认分支、归档和禁用状态。首次读取保存当前状态，后续只有内容变化才投递。收件箱始终更新同一条记录，个人记忆保留每次变化。后来开启个人记忆，会补收最近 24 小时内已记录的变化；后来开启收件箱，只补最近一次。选择「近期状态记录」可查看过去 24 小时的变化；在飞书主人私聊也可询问这条订阅最近变过什么。

快照默认在创建后安排首次读取，此后按工作台设置的时区每日 08:00 检查。可以修改每日时间，或选择至少 60 分钟的固定间隔。手动预览显示当前状态；预览已登记的快照还可比较它与上次记录的差异。

在订阅行点「运行记录」，可查最近 20 次已受理的手动拉取、定时拉取或自动重试。每次记录包含本次读取数、新增数，以及收件箱和个人记忆分别确认、待确认的数量。顶部列出当前仍待确认的条目和去向，历史记录保留当时的结果。核对补投是否成功时，可对照后续运行取得的回执。预览不会产生运行记录。也可以在 Web 主对话或飞书主人私聊中问“这条订阅上次拉取了多少，哪些还没投递？”

订阅读取失败后，首次自动重试等待两个拉取间隔，连续失败再逐次翻倍，最长六小时。来源读取成功后恢复原计划。若同一连接器连续三次调用失败，其下所有来源会先暂停出站一分钟。继续失败时暂停时间翻倍，最长六小时。订阅页分别显示连接器暂缓和上游限流的原因与时间。等待期间仍可补投已经保存在本机的条目。

启用中的订阅持续读取失败满 24 小时，收件箱会收到一张「知会」卡。只投递到个人记忆的订阅也会提醒。手工归档后，同一段故障不会再次打开卡片。来源重新读取成功、订阅暂停或删除时，卡片分别记录关闭原因。可以在 Web 主对话或飞书主人私聊问「这条订阅的故障提醒关闭了吗？」。核对积压是否补齐时，请查看订阅运行记录中的投递回执。

## 正式部署与更新

正式服务固定使用 `~/.super-mario/`，首次启动自动创建数据库。服务端使用唯一的正式 Web 端口 `48080`，浏览器和执行机代理连接同一地址。服务端和代理从 `~/.super-mario/runtime.env` 读取同一稳定的 `SUPER_MARIO_TOKEN`，升级和重启时沿用该值。

1. 确定待发布的提交，在该提交上运行 `npm test` 和 `npm run typecheck`。
2. 验证通过后，从该提交运行 `npm run build`。将产物放入 `~/.local/share/super-mario/releases/<SHA>/`，其中 `<SHA>` 为已验证的提交 SHA，构建期间正式服务继续运行原版本。
3. 构建成功后，将符号链接 `~/.local/share/super-mario/current` 切换到 `releases/<SHA>`，再执行：

   ```bash
   systemctl --user restart super-mario.service super-mario-agent.service
   systemctl --user is-active super-mario.service super-mario-agent.service
   ```

4. 确认两个服务均为 `active`，打开原正式 Web 地址，核对执行机已重新上线。分享链接使用 `/?v=<部署提交>#chat?token=<访问令牌>`。

## 安装命令行

```bash
npm run build
npm install -g .
```

也可运行 `npm pack` 生成安装包，再用 `npm install -g ./super-mario-0.1.0.tgz` 安装。打包时自动构建，不需要在目标机器运行 TypeScript 编译器。

用 `super-mario --help` 查看全部参数。

## 模型与访问配置

不带 `--demo` 时使用真实 pi 运行时。API Key 使用对应供应商支持的环境变量；例如：

```bash
export ANTHROPIC_API_KEY='你的密钥'
super-mario --provider anthropic --model '<可用模型ID>'
```

也可使用已安装并登录的 Codex CLI 作为 pi 模型提供者：`super-mario --provider codex-cli --model default`。default 沿用 Codex 当前模型，不复制登录文件。主 Agent 仍由 pi 管理对话和工具循环；CLI 只返回模型文本或工具请求，真正执行由工作台工具承担。原生工作/数据工具禁用，原生调用会被拒绝；每次建立模型 CLI 调用前通过短 `config/read` 预检配置。实测 Codex 0.162 仍声明 `request_user_input`，不能称为原生零工具或操作系统沙箱。收件分析的 pi 会话不配置工具。

模型 ID 需与所安装 pi 版本的模型目录一致。本轮已验证真实 Codex CLI 模型；其他云端 API 分支需按实际账号与网络验证。缺少模型或凭证时 Web 仍可打开，并显示助手不可用原因。

监听外部地址时必须设置令牌。在 Web 右上角连接状态面板输入同一令牌；也可使用 `http://主机:端口/#chat?token=你的令牌` 自动连接。页面读取后清理地址栏，在当前浏览器保存令牌 30 天，继续保留所选页面；兼容旧的 `?token=` 链接。代理连接也使用该令牌；不要将它提交进仓库。

| 参数 | 环境变量 | 单独运行 `super-mario` 时的默认值 |
| --- | --- | --- |
| `--host` | `SUPER_MARIO_HOST` | `127.0.0.1` |
| `--port` | `SUPER_MARIO_PORT` | `3000` |
| `--data-dir` | `SUPER_MARIO_DATA_DIR` | `~/.super-mario/` |
| `--token` | `SUPER_MARIO_TOKEN` | 本地可不设 |
| `--provider` / `--model` | `SUPER_MARIO_PROVIDER` / `SUPER_MARIO_MODEL` | 有凭证的可用模型 |
| `--demo` | `SUPER_MARIO_DEMO=1` | 关闭 |

## Web 模型配置

「Agent → 主 Agent 模型 → 更改模型」可选择模型 API 或 Codex CLI。API 模式填写供应商、模型和 API Key；OpenAI 兼容模式选择 `openai-compatible`，填写实际接口根地址（通常包含 `/v1`）。Codex CLI 模式使用服务端机器上已安装并登录的 CLI，模型填 `default` 可沿用 CLI 当前模型。可用 `cliCommand`、`cliConfigDir` 指定主模型启动器与配置目录；这是用户私有环境配置，不是产品默认路径，也不替代执行机配置。保存不执行登录，不验证认证。

点击「保存并应用」会重载主 Agent 和独立督办的运行时，后续对话使用新配置，无需重启服务。正在处理对话时返回忙碌提示。配置保存在数据目录的 `model.json`，权限 `0600`；读取接口不会返回密钥。同供应商密钥留空保留已保存值，切换供应商不复用旧密钥，勾选清除只清除工作台保存的密钥。保存并不代表真实模型请求已通过。演示模式保存后仍是演示，需要以非演示模式启动使用。

## 项目与记忆

打开「项目 → 电脑上的项目文件夹」，找到目标电脑，从它的用户主目录逐级展开，找到目标文件夹后点「添加」。主目录外的候选从 `/` 展开。只有候选行可以添加，中间的父目录用于导航。也可以搜索名称或路径，直接展开匹配项。浏览和展开只读取目录清单，点击添加才导入候选目录。

在「项目 → 工作区看板」把已添加的项目放入工作列。手工看板支持按绑定机器筛选，也可输入项目名、绑定目录、机器名称或 ID 搜索。浏览器会记住上次选择的手工或自动视图。可按当前筛选多选卡片，统一移动、置顶、归档或恢复。可拖动卡片调整顺序或移到另一列，也可用上移、下移按钮调序。批量操作成功后，可在同一看板撤销最近一次修改，恢复受影响卡片原来的列、位置或标记。关闭看板或有后续修改时，该撤销入口失效。归档的是看板卡片，项目和执行记录仍可从项目页打开。主人也可在 Web 主对话或飞书配对私聊按列、机器或目录询问有哪些项目。看板列由用户维护，执行和验收状态以相应记录为准。打开看板或单张卡片的「变更历史」，可按时间展开一次修改，核对当时的列名和变更前后的值。主人也可在 Web 主对话和飞书配对私聊追问某张卡片的变更。历史最多保留最近 500 次有实际变化的修改，按 16 MiB 容量清理较早的记录，最新一次修改始终完整保留。启用历史记录前的操作不会补录。

在看板切换到「自动分组」，可按当前执行、待办和待决定记录查看工作，并打开对应详情。已放入看板的项目汇总其执行，未放入看板的执行可以单独查看。每项显示归组原因。可按工作状态、机器或关键词筛选。切回手工看板后，项目卡片仍在用户指定的列。主人也可在 Web 主对话或飞书配对私聊询问哪些工作正在执行或需要处理。

找不到目标时，点「更多文件夹 / 手动绑定」，选择电脑并填写已有文件夹的绝对路径。旧项目也可在此补绑目录。保存时由所选电脑校验路径。同一台电脑上指向同一真实目录的路径复用同一个项目。

要创建文件夹，选择在线电脑，在手动选择区展开「新建文件夹」。只填名称并点「创建文件夹」，文件夹就建在这台电脑的用户主目录（`~`）下。「位置（可选）」可填主目录下的已有子目录（如 `code-work`）或已有目录的绝对路径。切换电脑会清空创建位置和名称。若提示不支持，请更新执行机代理，使其提供 `workspace.directory.create` 能力。

创建成功后，「文件夹」会填入执行机返回的完整路径。点「添加此文件夹」或「绑定此文件夹」后才保存项目。遇到重名时可改名。若提示创建结果未知，先到所选电脑核对目录。

添加后默认打开“工作区”，直接说出目标持续推进，不要求先填验收条件和预计分钟。项目同时提供待办、执行、资料和项目设置标签；“全部”用于汇总未归类工作。绑定电脑离线时目录和历史仍保留，不会自动换一台电脑执行。

在「项目设置」点「移除项目」并确认后，工作台会在项目列表和默认发现结果中隐藏该项目。电脑上的文件夹、文件以及工作台中的对话、待办、执行记录和项目记忆全部保留。需要继续工作时，展开「已移除的项目」并点「重新添加」，即可回到原项目。

待办顶部直接输入并回车添加。任何页面按 `c` 也可快速添加，使用顶栏所选项目；没有项目则放在“全部”。待办完成需要用户确认，不用 Agent 自述或执行结束代替验收。

「执行」可打开任务抽屉、查看计划，并在执行详情切换时间线、结果、终端。任务模式必须填写完成条件与预计分钟。结果未知时先核对，不重复发起。日常工作使用“工作区”里的项目对话；验收和时长只保留在手动发起的单次任务中。项目工作 Agent 和记忆 Agent 继续复用项目隔离的真实会话及来源记录。默认派发继承项目电脑与目录，已经明确批准的目录参数保持原值。

在「项目设置 → 记忆整理」点「查看整理会话」，可查看最近 60 条整理请求和回复。抽屉打开期间自动刷新，显示整理状态、最近开始和写入时间，以及失败原因。关闭自动整理后仍可查看历史。整理时会参考本项目的对话、待办、执行记录、当前工作决定和已有记忆页。整理时会核对当前执行轮次的验收记录。待办重开或验收证据变化后，提示词要求标明重开或失效；只有执行者自报时保留待核对状态。

项目跟进设置保存每日简报开关与时间、逾期提醒和自动处理偏好，由项目独立调度与策略消费（详见下文「答复、交付验收与项目跟进」）。少打扰策略需绑定受信目录并明确确认；未配置跟进的旧项目继续沿用全局简报规则。

在“项目 → 待办”点击待办可编辑截止日期和提醒时间。编辑窗口打开期间，尚未编辑的标题和备注会随服务端更新，正在输入的草稿保留。保存期间继续输入的标题和备注会留在编辑窗口，再次点击保存即可提交。切换所属项目时，输入框会等到保存结束再开放。两人同时修改同一标题或备注时，页面保留草稿并显示最新内容，核对后可再次保存。通过 Web 或飞书对话修改时，助手也会先核对原文，遇到冲突请用户决定。时间按浏览器本地时区填写。已填日期时，留空截止时间表示全天，填写时刻则按本机时区保存。启用「待办日历」插件后，可在同一项目切换日、周、月视图，从时段添加待办、编辑具体截止时间或拖动改期。清空字段再保存即可取消。只改标题或备注会保留原始时间与提醒认领；提醒到点后列表显示“已记录”，不代表外部渠道已送达。提醒检查需在“Agent → 自动跟进”开启，渠道发送仍需现有授权。功能覆盖、差距和后续优先级见 [功能清单](feature-inventory.md)。

「记忆」顶部写一句话并点“记住”，会直接保存为记忆；粘贴链接则进入整理队列（需要整理 Agent）。默认归入个人记忆。个人、全局、项目分别管理，全局表示通用工作原则，不表示公开。可用“详细添加”直接保存或在详情抽屉编辑；跨层同名只提示差异，不自动覆盖。来源未记录时如实标注。

在「记忆」页底部的「设置与队列」（或「Agent → 高级 → 界面 → 设置记忆整理 Agent」）选择在线电脑和 Codex 或 Claude，单独启用。电脑需要提供 `executor.knowledge.*` 并预先完成命令行登录。此常驻整理会话不占用主对话；主模型配置也不会替代它。

公开 HTTP(S) 文本、HTML、Markdown 来源可自动提取。在「设置与队列 → 受保护来源读取」可独立启用飞书文档、知识库文档、UTF-8 文本附件、PDF 文字层和 DOCX 读取。默认复用已核验的个人飞书账号；高级设置可指定已配置的 CLI 连接名称和精确受信域名。此开关不登录、不申请权限、不启动消息采集，保存配置也不表示有读取权限。附件输入和提取正文各限 1 MiB，PDF 最多 100 页；扫描件不做 OCR，旧版 Office、XLSX/PPTX、公开链接中的二进制附件及需脚本加载的正文暂不支持，可粘贴正文。PDF/DOCX 在独立解析线程中处理，取消或超时会终止该线程；不需要另装系统 Office/PDF 转换程序。

从 Web 直接提交链接代表本次读取请求；Agent 投放的受保护来源先进入「待主人确认」，在对话批准后才读取。确认只绑定本次链接、知识归属和读取身份，不扩大账号权限。来源、项目、机器人或身份失效后旧确认不可复用。账号正在核验时来源留在队列等待。读取、整理和结果未知分别报告；未知任务须核对后显式重试，重复提交同一次重试不创建多个来源。整理期间人工修改的记忆不会被过时结果覆盖。

个人知识与每个项目分别使用常驻 CLI 会话；只注入该范围的已有知识和全局工作原则。Claude整理保留所选配置目录的用户连接配置，排除项目/本地配置，并使用安全模式及工具限制。执行机沿用自身 launcher/profile，最多保留四个范围会话，仅回收空闲会话。暂停或切换整理执行者需要核对远端会话。队列随事件更新，保留尚未保存的设置草稿。

来源在既有读取上限内完整保存到 raw，不为模型预算静默截断。模型来源输入预算为 200000 字符（包含头信息和引用）；超限明确失败并保留原始资料，需拆分后重新提交。读取来源既有的 1 MiB 上限仍有效。

编辑期间若其他人或整理 Agent 已更新知识页，保存会提示版本冲突并保留草稿。核对最新版本并继续编辑时，未动过的字段会采用最新值；你改过的字段保留草稿，可核对后重新保存。

在「记忆 → 会议日回顾」可选日期、时区和项目，按当地时间的上午、下午、晚间查看会议来源与整理状态，并从已关联的知识页打开原文。可在回顾列表或「记忆整理」队列修改会议来源的显示标题，留空恢复登记时的标题。原始转写和知识页标题分别保留。在顶栏搜索当前标题或登记标题，可从「会议」结果打开原文；尚无关联知识页时会定位到整理队列。匹配超过五场时，可点「查看全部匹配会议」逐页查看。Web 或飞书项目对话也支持按标题查找会议，无需知道日期。页面默认使用浏览器时区。查询到来源后，点「将回顾问题加入对话草稿」可把日期和时区带入对应项目对话或主对话，核对草稿后发送。也可在 Web 或飞书项目对话中询问某天的会议回顾，并指定时区。助手按会议开始时间列出已登记的来源，读取可用原文；缺少会议日期的资料单列数量，尚未整理的资料显示进度。

在知识页展开「查看原始资料」中的会议来源，点「准备会议交接稿」，可填写接手方的任务，再到所属对话核对草稿。需要附用户核对的转写时，勾选「附上这份会议转写」；超过 5000 字符时保留首尾各 2500 字符，并标出省略位置。也可在飞书项目对话中指定会议，要求起草交接摘要；明确要求附转写时，助手可读取同一份交接节选。

在 Web 或飞书项目对话中询问会议行动项进度时，助手可按行动项关键词核对当前项目待办。回复应区分会议约定、待办登记期限和验收状态；没有对应记录时，进度待确认。在知识页正文选中一行或连续多行，点「将正文选中行加入待办」核对后确认。也可在 Web 或飞书对话里指定同一页的一项或多项。一次提交中的任一项无法核对时，整批不会写入。待办备注保留来源页、版本和原文。重复确认同页同一行会返回原待办。在正文选中原行后点「查看选中行的待办进度」，或在对话里询问进度，可核对已关联待办的当前标题、登记期限和验收状态。知识页和 Web 对话中的「查看待办」可打开相应待办详情。

在记忆页搜索标题、别名、已确认事实或正文，多个词用空格分隔，顺序不限。完整命中所有词的标题优先显示，其次是同一别名命中所有词的页，再次是同一行事实或正文命中的页。结果会标出匹配词，默认展示两行正文摘录，可点「查看更多命中行」展开后续匹配。点击标题可查看全文，点击正文摘录可在编辑框中选中对应行。知识页可设置 P0 至 P3 重要级。列表按 P0 到 P3 排列，未设置的页列在最后，同级按已记录的相关度（0 至 100）从高到低排序，未评分列在已评分之后，再按最近更新排序。在 Web 和飞书对话中可指定相关度下限，也可给指定页评分或清除评分。可以同时筛选重要级、标签和关键词。Web 和飞书助手也可按指定重要级查找知识，或按你的要求为指定页设置、清除重要级。

如需保留定稿，在「正文维护方式」中选择「仅手工编辑」并保存。整理器仍可读取该页，新材料需另建页；在 Web 中仍可手工修改正文或恢复自动整理。

已确认事实的变更会记录保存时间和写入入口，可在详情与历史修订中核对。旧版本缺少来源记录时显示未知。可在编辑框的「已确认事实」中记录经你核实的结论。助手核对同一事项时会优先参考该字段；整理器更新正文会保留它。也可在 Web 或飞书对话中明确指定知识页，要求追加、更正或删除一条已确认事实。更正和删除按原文片段定位，遇到重复表述需先明确是哪一处。

在「别名」中可逐行填写旧称，保存后 Web 和飞书助手都可按旧称查页。也可在对话中指定知识页和别名，请助手添加或移除该别名。在编辑框的「标签」中每行填写一个标签。列表可按标签和关键词同时筛选，也可在 Web 或飞书对话中让助手按标签查找当前范围的知识，或明确指定一页添加、移除某个标签。

在记忆详情展开「查看历史修订」，可阅读最近保存的标题、正文、别名、标签、重要级和相关度，点「查看上一版」可对照更早的记录。把页面显示的八位修订号和知识页告诉 Web 或飞书助手，即可核对指定版本。短号无法唯一定位时，使用修订链接中的完整版本号。记忆变更归属时，翻阅会停在当前范围的首版。点「将此版载入草稿」可恢复该版标题、正文、别名、标签、重要级和相关度，核对后点「保存」才会写入新修订。版本来自知识目录已有的本地 Git 历史。也可在 Web 或飞书项目对话中询问某条记忆的上版内容；助手能按版本比较已保存的表述。Web 回复中的「查看修订」可打开被引用的版本，飞书回复可按页标题、保存时间和版本短号核对。

在知识页的「查看原始资料」展开一份来源，有登记网址时可点「打开原始网址」。也可在 Web 或飞书向助手询问该知识页的来源网址。反过来，给助手完整网址可查到有导入记录关联的知识页。查询参数和页内定位均参与匹配。也可以不提供网址，直接问项目助手哪些资料在排队、待批准或整理失败。数量按提交次数统计，重试单独计数。在 Web「设置与队列」可组合筛选整理范围和状态。询问整理进度时，助手可按该网址列出历次提交、失败原因和重试状态。Web 答复可直接打开对应队列记录。在「设置与队列」点击「查看整理结果」可打开该次导入关联的知识页和来源。

整理会议材料时，知识页会附上来源收件记录和原始资料路径。在记忆详情展开「查看原始资料」，选择来源标题即可核对整理时保存的原文。原文含 Markdown 标题时，展开「文档大纲」并选择标题即可跳到对应行。对于登记的飞书文档或指向文档的知识库链接，可展开「查看飞书文档评论」。工作台使用受保护来源读取设置中的飞书账号重新查询，展示原文引用、回复和解决状态。「刷新评论」可读取最新结果。部分返回时界面会标明，权限不足时仍可阅读原先保存的正文。要发表意见，可评论整篇文档，也可先选择原文中的文字。工作台会在当前飞书文档中定位这段文字，把评论发到对应段落。无法唯一定位时需重新选择。回复已有讨论或更改解决状态时，先核对文档和目标评论，再确认操作。要提及同事，在评论或回复中输入 @ 和姓名，选中联系人，并在确认窗口核对提及名单。未选择联系人的同名文字会按普通正文发送。写入后刷新列表即可核对飞书中的内容。结果未知时先打开原文档检查，避免重复发送。启用「消息引用」时，可点「引用原文追问」选择文字。项目资料进入该项目工作对话，个人资料进入主对话；已有问题保留在草稿中，可编辑后发送。整理器只可更新本轮完整读取的已有页。若长页仅有节选，请把新增议题整理为关联的新页，以保留旧页全文和来源。

知识整理要求派料和停止前核实远端 `scope/provider/workerId`。旧节点未确认时不派料、不误停、不删除绑定；同一电脑及 CLI 类型可安全暂停本地派料，切换前仍需远端确认。现代节点明确回显目标 scope 且确认无 worker 时才可清理旧指针。旧执行机需更新代理后再启用整理；暂停派料不表示远端进程已经退出。

数据目录的 `plugins/knowledge-local/` 保留原始资料、记忆正文、索引和独立 Git 记录。用户无需操作 Git，不默认推送远端。电脑断线后读取原任务结果，不重复提交；进程本身重启后未确认任务标为未知。

自动候选来自执行机上的 Codex 或 Claude 用户会话。只有 Git 仓库标记、配置中的目录记录或自动派生的子会话，都不足以让目录成为自动候选。自动发现只列出现存目录，排除用户主目录本身、CLI 配置目录、系统临时目录和 Git linked worktree 等路径。如需使用被过滤的目录，可手动绑定现有路径。电脑代理在读取上限内检查本地会话是否有用户输入。达到上限或读取失败时，面板会提示，仍可手填路径。主 Agent 可用 `projects_discover` 查看候选，再用 `project_create` 绑定目录。

## 执行机代理

先用令牌启动服务端，再在执行机运行：

```bash
SUPER_MARIO_TOKEN='同一访问令牌' super-mario-agent \
  --url http://服务端地址:3000 --name 我的执行机
```

代理会自动重连，机器标识保存在 `~/.super-mario/agent/machine.json`。可以用 `--data-dir` 指定独立目录。

执行机可使用 Codex、Claude Code 或 Pi CLI。在项目发起执行时选择对应电脑的执行器，主 Agent 也可通过执行器列表发现并派发。Pi 使用执行机上配置的模型提供方；可用 `--pi-command <路径>` 或 `SUPER_MARIO_PI_COMMAND` 指定启动程序。Pi 可用于外部任务和知识整理。整理使用支持 `agent_settled` 事件的 Pi RPC CLI（项目依赖版本 1.5.2），禁用工具和扩展。执行机使用已安装的 `herdr`。代理会在 PATH 和用户的 `~/.local/bin` 中查找，也可用 `SUPER_MARIO_TERMINAL_COMMAND` 指定路径。服务停止时，可以在多屏现场启动宿主。

## Web 工作台

「Agent → 定时工作」支持单次、每天、间隔和高级 cron。也可让主 Agent 提出周期工作。先确认创建配置；到期派发仍生成独立的执行审批，不因定时配置获批而直接运行。事实简报仅汇总已接入事实，不调用模型、不外发。结果未知、仍待批准或执行未结束时暂停生成新动作，取消计划不会终止已经派发的任务。

收件箱按私聊、群@我、群聊和 Agent 协作筛选，人侧待决策与 AI 待执行分开。列表先显示 50 条，再按需加载；搜索、筛选和计数使用全部已加载来源数据，不只检查展示窗口。归项目保存遇到版本冲突时保留选择，只有再次明确点击才使用最新已知版本提交。非个人会话的逐条分类使用独立无工具会话，失败时回退规则。飞书个人会话先保留原文，再由主 Agent 按联系人合并整理。

首页优先事项和项目总结中的待办标题可打开具体待办，执行标题可打开执行记录。待办详情地址支持刷新和收藏。

在 Web 或已绑定的飞书机器人对话中，可以问“北京时间本周有哪些待办到期”。询问“今天”或“本周”时，助手优先采用问题中指定的时区，默认采用工作台简报时区。助手可按截止时间查询并排序，项目和事项机器人只返回绑定范围内的待办。也可问“还有哪些没完成”“哪些已经完成”或“哪些逾期了”。逾期仅统计有截止时间、已经到期且仍未完成的待办。也可问“哪些待办还没定期限，按优先级排列”。只设置了提醒的事项仍算未定期限。问“哪些待办派过执行”可查到有关联执行记录的事项，包括执行已结束但待办仍待验收的情况。指定一条待办后可以追问备注、提醒、等待谁以及记录过哪些决定。同名时可用项目或待办 ID 指明。可以说“把这项的截止时间改到北京时间周五下午三点，保留原提醒”或“取消这项的截止时间”。如果有人同时改了期限，助手会请你核对最新时间。

在 Web 主对话或项目工作对话打开「搜索本对话」，输入记得的一段原话。用「搜索内容」可查正文、用户发言开头的引用、可读的附件名、工具名和工作事件。选「工具入参」可查当时的对话检索词和类别。选「工具返回」可查当时检索返回且目前仍可读取的原话，以及当时查到的会话状态。命中项会标明工具名，可定位到调用所在的回复；工作事件可查进行中的公开进度，以及有关联记录的执行结果。同一条消息有多个命中时会分别显示。点击摘录即可回到原消息，也可以继续查更早的结果。已选择项目或待办时，搜索使用当前范围。也可直接问助手这段对话里提到某个词时说了什么。

打开项目待办详情的「关联的项目对话」可按时间回看提问与回答，点击摘录会定位到项目会话中的原消息。点击提问旁的「查看对应回答」可查看直接回复和处理状态。此功能由对话历史搜索插件提供。点击「就此待办提问」，可以在项目工作区围绕该项发消息。输入框显示关联待办，事项草稿和普通项目草稿分别保存。待办详情中的「本事项等你处理」显示关联执行或来源消息明确指向该事项的待处理交互卡，可在原卡回答。在「执行历史」中可按轮次核对答复回执，分别查看执行会话输入或工作台本地处理是否确认。没有关联执行轮次的对话答复也在此显示。回答提问后，项目对话会沿用来源消息的待办归属。若待办已移入其他项目，工作台记录失败，需在当前项目重新确认。原对话接收后续输入与飞书消息送达分别核对。也可以在 Web 或飞书中问“这件事等我决定什么”。

在编辑待办中选择同项目的「上级待办」，可建立或解除层级。待办列表和详情都显示直接子项的完成数，按标题搜索或筛选期限时仍统计全部直接子项。详情支持跳转上级和子项。移动项目时会解除和原项目的上下级关系。可在编辑窗口选择同级的「前置子项」，详情中逐项显示完成状态。更换上级会解除原有同级依赖。如果另一端刚修改了前置项，工作台会拒绝过期的修改。请重新打开待办核对当前依赖，再决定如何调整。依赖满足后可以继续处理，子项和上级仍各自验收。

编辑待办时可填写或清除负责人姓名，详情和列表会显示登记结果。Web 和飞书对话可按登记姓名查询某人负责的事项。也可在编辑窗口选择当前项目已登记在执行记录中的电脑和会话作为负责方。切换为个人或会话时会替换原负责方；移入其他项目后需重新选择会话。Web 列表可用“电脑标识 / 会话标识”检索；对话中可以问“这台电脑的这个会话负责哪些待办”。登记不会通知对方或启动执行。待办列表的搜索框支持标题、备注、负责人和“在等谁”。在 Web 或飞书对话中问“哪些待办还在等审核组回复”，助手只按登记的等待对象查找当前范围内的未完成事项。在待办详情展开「回复跟踪记录」，可以在提醒停止后查看匹配时间，重新开始等待后仍能辨认上一轮。追问某项“收到回复了吗”时，助手会查看该项的回复跟踪周期。匹配成功可报告直接回复的时间；尚未匹配或没有跟踪记录时，实际回复情况仍待核实。

待办列表可按今天、本周、本月或无截止日期筛选，也可在各分组内按最近更新、截止时间或优先级排序。日期范围使用浏览器本地时间，周视图、月视图和列表按浏览器地区确定每周首日。月历同日最多直接显示三项。超过三项时显示前两项，点击「还有几项」可在日视图查看当天全部匹配的待办。向助手核对同一周时，可以直接给出周视图标题上的起止日期。今天、本周和本月都会保留未完成的逾期事项。筛选和排序保存在当前浏览器。

登记或编辑待办时，可选高、普通、低优先级。未设置的事项按普通处理。Web 和飞书对话可直接说“列出项目里高优先级的未完成待办”或“把这项调为低优先级”。

重复要求助手登记待办时，同一项目、同一上级下标题和截止时间一致的未完成事项会返回原记录，原备注和提醒也会保留。已有多条匹配时，助手会请你选定具体事项。

说“半小时后提醒我跟进这项待办”可以单独设置提醒，说“取消这项提醒”可清除提醒。两种操作都保留截止时间。只有未来时间可以登记为新提醒；对话中确认设置成功，只表示工作台已保存该时间。

在 Web 或飞书项目对话问“本项目有哪些事等我决定”，可以查询待批准的申请、待回答的问题、待启动的计划，以及已归类且需要确认收取或发送的机器人信件。独立收件需要转待办或忽略时也会列入。已合并的消息只按会话展示。合并收件会话需要你补充信息时，清单会列出助手的问题。Web 链接可打开该会话，回复后由收件助手继续处理。询问完整清单时，助手可分批查阅。Web 回复里的「查看待决定事项」打开对应卡片，由你决定如何处理。飞书回复按类型列出标题。事项对话只列该待办范围内的记录。

在消息详情点「处理与建议」，可独立讨论该条来源，或手工编写待办、派发、回复、处理结论四类建议。来源关联待办后，「处理与建议」显示该待办的当前标题和完成状态，点标题可查看详情。派发建议会显示本次执行的最新状态，点「查看实际执行记录」可核对执行详情。需要你回答的问题和待批申请列在该次执行下，点标题可打开对应卡片。可询问当前建议的审批进度。模型可核对本来源版本最近更新的 20 条建议及对应审批状态，也能读取当前来源、同范围知识和全局原则。飞书回复建议卡还显示投递记录中的状态，可打开对应发件记录；结果未知时先核对再处理。建议卡显示审批状态，待批准时点「去对话审批」可打开对应申请。保存建议不执行；编辑生成新版本，提交审批只绑定当前具体内容。到对话批准后才调用原有待办、Run、发件箱等操作。项目改绑、归档、插件启停或读取身份改变后旧确认失效。历史讨论与回执保留。重启或会话缓存释放后，助手从当前绑定恢复最近的完整问答，最多 12 轮、正文合计最多 24000 个 UTF-16 码元。较长消息只取首尾，提示词要求在回答依赖缺失原文时说明缺口。

在「渠道 → 个人消息采集 → 个人消息 /ai 设置」开启指令，并开启个人消息采集。在已允许观察的群或私聊发 `/ai 刚才定了什么？`。默认只有本人能触发，群聊需要填写群 ID。可另行指定触发人的 open_id、指令前缀和上下文条数（默认 10）。只处理启用后发出的新指令。开启时复用个人采集，每轮完成约 30 秒后检查新消息；积压分页按原有节奏继续。

工作台按个人账号、会话和话题选择上下文，使用已配置的只读收件分析模型。回复保存在原消息的「处理与建议」，可以编辑、丢弃或提交审批，获批后才发送。「个人消息 /ai 设置」显示近期触发结果。模型不可用或分析中断时，先核对结果，再用一条新指令发起分析。

个人回复只使用采集该消息的已核验账号，以及连接器已观察的原消息引用；旧聚合来源或缺少依据时只可保留草稿。机器人回复校验原机器人、群授权和线程。回复不会自动登录、申请权限或改发其他账号。只有明确送达才把原收件标为已处理；结果未知时在发件箱保留未知，禁止自动重发，待办不因此自动完成。原文、项目或账号在发送期间变化时，不会把新内容一起归档。

收件箱的待 AI、执行中和待人决策，来自实际分析请求、Run 和阻塞事项。主 Agent 共享快照只汇总处理状态与回执，可用只读工具查询有权限的详情。未知的模型分析可在核对后显式发起新请求，不会重放原审批或外部动作。

在 Web 编辑或请助手修改提醒时，如果另一入口已更改这轮提醒，系统会显示最新设置，供你核对后重新保存或确认。待办日历的闹钟标记表示该待办仍有尚未触发的提醒。在 Web 或飞书对话中可查待触发或已触发的提醒。待办详情显示本地触发时间，打开「飞书提醒投递记录」可查看当前状态和更新时间，也可问助手这次提醒是否已发到飞书。助手读取当前提醒版本的投递记录；改期前的发送记录只属于旧提醒。待办日历标出浏览器当地时区。向 Web 或飞书助手询问某天到期的待办时，可指定日历上显示的时区，服务端会按该时区匹配截止日期。待办日历的日、周视图打开时会定位到当前时间或最早到期事项附近。切到没有待办的其他日期时从 08:00 开始，同一视图刷新待办时保留滚动位置。日、周视图里，点击空白时段会按点击位置预填最接近的 15 分钟，键盘激活同一时段则预填整点，日末栏预填 23:59。填写标题后点击「添加」才会保存。点击日历底部的「没有截止日期，查看列表」会切换到「无截止日期」筛选，保留当前项目和搜索词。拖动待办时可预览落点时间，松开后按最近的 15 分钟保存。月视图拖动只改日期，提醒时间单独保留。若另一窗口已更改截止时间，工作台提示冲突。核对日历中的最新时间后再拖动；在编辑窗口遇到冲突时，关闭后重新打开即可读取最新时间。

在顶部搜索框输入关键词后，可用上下方向键逐条选择结果，Enter 打开，Esc 收起。项目对话的搜索结果稍后到达时，已选中的链接会保持焦点。

在「插件配置 → 阅读字体」可分别选择正文字体和代码字体，也可填写本机字体名称。阅读字号提供小、标准、大三档，保存后立即应用到工作台。留空并保存可恢复默认字体。

在「插件配置 → 快捷键设置」可录入组合键、清除绑定、停用单个命令或关闭全局快捷键。绑定冲突时可取消或替换；设置保存在当前浏览器。按默认的 `?` 可查看当前有效的快捷键。

直接打开工作台默认进入「首页」。在「插件配置 → 启动页」可选择主导航页面或已启用插件的页面。设置保存在服务端，同一工作台的浏览器共用。已选插件暂不可用时打开首页，重新启用后恢复原选择。带页面或消息位置的链接直接打开目标。项目对话翻页位置失效时，可点「返回最新消息」；读取失败可在原位置重试，项目草稿会保留。主对话旧链接找不到原消息或对应插件不可用时，页面会说明原因，可点「返回最新消息」继续对话。顶栏可搜索待办、执行、记忆和项目。启用「对话历史搜索」插件后，可按正文分别查找主对话和未归档项目工作对话中最近五条匹配消息。主对话和项目消息的完整搜索结果可按发言角色和浏览器当地发言日期筛选。询问项目助手“昨天讨论了什么”时，助手按指定时区或工作台时区查阅历史消息。项目命中显示项目名称。在 Web 或飞书的项目对话中，可让助手只查用户提出的要求，或只查助手之前的答复。让助手核对完整原话时，检索和读取按正文版本关联。若途中发生编辑，助手会重新检索并核对当前原文。打开带版本的「查看原文」链接时，若引用后正文又有修改，项目对话会提示并显示最新内容。点击可定位原文并查看上下文，刷新会保留位置。项目工作对话每页最多显示 60 条消息，点击「较早消息」或「较新消息」可连续翻页，点击「返回最新消息」回到末尾。项目选择用于新对话和快捷添加。服务访问令牌在右上角连接面板，状态显示已连接或重连中，恢复连接后自动读取数据。旧页面书签会跳到新的对应位置。

启用「对话图片」插件后，Web 主对话和项目工作对话支持选择或粘贴截图。可同时填写问题，也可只发图片。发送后可在原对话查看附图。每条消息最多 20 张，支持 PNG、JPEG、GIF 和 WebP，发送时每张最多 3,750,000 字节，整次请求最多 32 MiB。已配对的主人也可在飞书机器人私聊中发送图片。回答图片问题需要支持视觉输入的模型；本地演示只报告收到的图片数量。后续提问可接着讨论已有的文字分析。要核对新的图像细节，可点击原会话里的图片，选「编辑到草稿」再发送。

发送前点图片旁的「编辑」，可画框、用画笔标注、裁剪或旋转。保存后，草稿显示编辑结果。启用「对话草稿」后刷新页面，再次编辑仍可撤销。点击已发送的缩略图可放大查看、切换图片或下载原图。浏览器支持图片剪贴板时，也可点「复制图片」。

启用「对话文件」后，在 Web 主对话或项目对话点「添加文件」，可将文件与问题、图片一起发送。已配对的飞书主人私聊支持富文本消息。标题、段落、链接、提及和代码保留在原对话，启用「对话图片」后，机器人核对原消息，将内嵌图片按正文顺序一起交给助手。原会话可查看图片，撤回飞书原消息后图片链接失效。视频显示为占位。在同一段私聊中直接回复一条已接收的图片或图文消息，可以结合原图追问。直接回复已接收的普通文件或合并转发记录，也可就原文提问。助手按实际取得的正文或摘录回答；原文件已撤回时会提示无法读取。Web 独立对话记录中的「查看引用原图」和「查看引用文件」都可定位到原消息。主人还可直接发送文件，也可发送合并转发的聊天记录。机器人整理本次转发的直接子消息，保留发言人、时间及可读文字，最多 30000 个 Unicode 字符。图片、文件和嵌套转发显示为占位。在原会话可通过「转发的聊天记录.txt」查看材料。每条消息最多 20 个文件，单个文件最多 200 MiB。在原会话点文件卡的「预览」可查首页或文字摘录，也可以直接下载原件。PDF 预览显示实际首页。Office 和 iWork 文件优先显示文档内附的预览图；缺少预览图时，按格式显示可读取的文字或原因。启用「对话草稿」后，刷新可恢复待发文件；若上传凭据过期，点「重试上传」再发送。

助手可读取 UTF-8 文本、代码、CSV，以及 PDF、DOCX、XLSX、PPTX 的文字。PDF 和 DOCX 的解析上限是 1 MiB，XLSX 和 PPTX 是 8 MiB。每份文件最多提供约 8,000 字符的摘录，单轮合计约 24,000 字符。扫描件没有可提取文字、不支持的格式、超限或截断，都会标明。只发文件时，助手只读分析。

在「Agent → 主助手资料」可更改主助手名称，并查看模型、执行机和全局飞书机器人的连接状态。主对话气泡使用当前名称。新一轮 Web 主对话或全局机器人会话会读取这个名称；项目助手和机器人渠道各自保留原有名称。


在「Agent → 助手技能 → 管理技能」选择不超过 4 MiB 的 ZIP。包根目录或唯一顶层文件夹内须有 `SKILL.md`，其中 YAML 元数据包含 `name` 和 `description`。核对文件清单后点击安装。在 Web 主对话或全局飞书机器人中点名技能即可请求使用。模型按需读取说明和包内文本，安装不会启动包内脚本。管理面板支持查看文件和删除导入的技能。内置的 `workbench.work` 工作指南随技能插件提供，涵盖待办、派活、进展、验收、执行机、会话和项目代码。在这两个入口询问进展时，助手可按指南查执行记录和待办验收状态。

在「Agent → 执行者与电脑」打开电脑详情，可手动读取该机 Codex、Claude Code 和共享技能目录的名称、简介和来源。代理只读本机清单。电脑离线、旧代理缺少能力或读取失败时，页面显示对应状态。Web 主助手和全局飞书机器人也可按机器查询。

在 Web 或飞书机器人中询问某次会议的决定时，提供会议主题或粘贴纪要。助手可检索当前范围内已整理的会议资料，按正文区分决定、建议和待确认事项。追问原话或出处时，助手可按知识页关联的来源分段读取已保存的原文。助手可以按关键词搜索长原文。Web 回复中的「查看原文」直接打开相应来源，带行号的引用会高亮命中行；飞书回复使用来源标题和原文位置。只有日历邀请或未读取的链接时，需要补充正文。

发送后遇到断线或服务拒绝，可在主对话或项目对话的「待确认发件」中查看原记录。「核对回执」只查询受理状态。「重新发送」先查原请求号，服务端明确查无回执时才用同一请求号提交原文和原附件。另写的草稿会保留。「移除记录」只清除本地发件记录。启用「对话草稿」后，同一标签页在 24 小时内刷新可找回原内容；浏览器无法保存时，原内容仅在当前页面可用。普通文件使用原上传凭据，过期后需要重新选择文件。

Web 主对话和项目对话中的答复如果在工具执行前失败，可以点击「重试本轮」。工作台会重新核对原项目、待办及附件权限，使用原文和原附件发起一次新请求。重复点击可查回同一次受理记录。原答复及失败原因可继续查看。手动停止、服务中断或已经调用工具的轮次，请先核对执行记录。

在主对话点击「办公文件」，填写标题、格式和源内容，可生成并下载 Word、PowerPoint 或 Excel 文件。Word 和演示文稿接受 Markdown，Excel 接受 CSV 或含 sheets 的 JSON。Web 主对话、项目对话及已配对的全局或项目机器人私聊也可生成文件。在 Web 原答复的文件卡上可预览、下载。停用「对话文件」后仍可从「办公文件」面板下载。撤回飞书原消息或重新配对后，该私聊文件的两个下载入口都会关闭。执行机包含本地命令 `super-mario office docx 报告.md -o 报告.docx`，格式参数也支持 `pptx` 和 `xlsx`。CLI 可嵌入 Markdown 源文件目录内通过相对路径引用的 PNG、JPEG、GIF。Web 可嵌入源内容自带的图片数据。输出文件已存在时，选择新的文件名。已有文件可在「办公文件 → 查看已有文件内容摘要」上传检查，或在本机使用 `super-mario office check <文件>`。

启用「回复翻译」后，在主对话或项目工作会话的助手回复下点「翻译回复」可查看简体中文译文，点「查看原文」可切回。译文在内存中缓存，更换模型后重新翻译。每条回复最多支持 32,000 个字符，演示模式会提示翻译不可用。

在收件箱打开一条飞书原始消息，可选择目标语言并点「翻译消息」。勾选「本会话自动翻译」后，在本浏览器打开同一账号、同一会话的外语消息详情时会自动显示译文。在个人消息分组点「打开会话」，可见的外语消息会在原文下方显示译文。自动翻译默认关闭。

启用「编辑为新消息」后，可在自己发过的消息下点「编辑」，修改正文后手动发送。原消息仍在历史中。输入框原有草稿时，可点「撤销替换」恢复。

启用「消息引用」后，在主对话或项目工作对话的消息下点「引用」，可附上问题或更换、移除引用。只需讨论其中一段时，点「选择引用片段」，在原文中选取文字，再点「引用选中段落」。点「引用到其他对话」可将当前引文放入主对话或项目工作对话的草稿。目标已有引用时，按钮会标明替换；已写的问题保留，打开目标对话后可以继续编辑并手动发送。发送后点击引用摘要可展开实际发送的引文。飞书直接回复一条消息时，助手可参考同一机器人、聊天和工作范围内已处理的收件，或有发送回执的普通机器人回复。直接回复已完成的进度卡时，助手可参考卡上实际显示的答复正文。卡片尚在更新或最终更新失败时，该卡片的答复正文不可用。找不到对应原文时，助手收到缺失标记。

启用「对话草稿」后，主对话、项目工作对话和收件处理指令会在当前浏览器保留未发送的文字。主对话按选中的项目分别保存，收件处理按来源会话恢复。刷新页面后仍需手动发送。在主对话或项目工作对话的空输入框按 ↑ 可取回已发送的内容，↓ 返回较新的内容。按 Ctrl+R 可用多个关键词搜索本浏览器同一身份下的发送历史。Esc 保留当前草稿，Enter 将选中内容放入输入框。每个会话最多保留 100 条已获受理回执的正文。收件处理指令也支持 ↑、↓ 和 Ctrl+R，检索范围限于当前来源绑定的处理会话。主对话和项目工作会话为每次发送保存请求号。回执丢失时可点「核对发送回执」，也可在原浏览器标签页用同一份草稿重试。服务端按请求号返回已入库的消息，避免重复调用模型。

启用「常用提示词」插件后，可在插件设置中管理模板，也可从自己发过的消息保存正文。删除模板时，在对应条目确认；取消后模板仍可使用。主对话、项目工作对话和收件处理对话都可在输入框键入 `/名称` 查找模板。候选最多显示 25 条，按名称完全匹配、开头匹配、包含关键词的顺序排列。同一组沿用你在管理页设置的顺序。用上下方向键选择候选，按 Tab 或 Enter 将正文填入草稿，仍可修改后手动发送。读取失败时保留输入，可点「重新读取提示词」重试，或按 Esc 关闭候选。模板库最多保存 100 条，每条正文最多 8000 个字符。同时编辑同一模板发生冲突时，刷新列表可对照当前保存的正文，草稿保留在编辑框。编辑时可看到重名和超长提示，按 Ctrl+Enter 或 ⌘+Enter 可保存。

「最近记录与来源」显示计划时间、服务端开始处理的时间和延迟。若先前的审批或执行阻止了本次触发，记录会显示先前那期的计划时间和当时的原因。旧记录缺少处理时间或跳过原因时会标明。计划修订后，历史记录按当时的版本显示派发或简报动作。展开记录，点击已生成简报的「查看简报原文」可核对当次正文。待处理审批可直接打开对应审批卡。已关联执行记录的派发可查看执行详情。超过 20 次触发时，点「查看更早记录」可继续翻阅。也可以向 Web 或飞书助手指定计划和触发时间查询。

「定时工作」分为重复计划和一次性安排。可按频率筛选，一次性安排按计划时间从早到晚排列。每页显示 100 项。可翻页查看当前范围内的全部计划。

在 Agent 页的「定时工作」可以暂停和恢复已生效的计划，也可以在 Web 或飞书对话中指定计划并要求暂停或恢复。派发计划的「查看执行要求」显示已保存的提示词、完成标准、执行者、工作目录和预计时长。也可在飞书或 Web 对话中按计划名称查询。

「从模板创建」提供会前准备、周报草稿、执行巡检和下班前盘点。可修改排期、目标和验收标准，选定执行者后提交创建审批。选择「每周」可勾选重复日期，填写当地触发时间和 IANA 时区。周末对应周六和周日。选择每天、每周或高级 cron 后，可在提交前核对规则时区的下三次触发时间。也可让飞书助手只试算排期。周期计划可填写结束时间，表单会标明浏览器时区。到达该时刻即停止触发，服务停机跨过截止时间后也不再补跑。已生成的派发审批仍可单独处理。周期计划也可以「跳过下一次」。Web 和飞书助手均可按指定时间跳过，触发前可撤销。后续排期照常，历史会标明由你跳过。暂停期间停止后续触发，已经生成的派发审批仍需单独处理。恢复时，调度器会按原计划合并错过的触发。

Agent 页的「主助手资料」会按当前范围列出最近三项已生效、尚待触发的定时工作。Web 和飞书助手可按同一份计划回答「接下来会自动做什么」。

在项目工作对话中打开「工作指令」，可保存本项目的术语、工作方法或验收要求。编辑框显示草稿所依据的版本及保存时间。Web 和飞书项目助手也可按当前记录回答何时保存或清空了这一版。另一窗口修改同一项目后，未编辑的说明自动更新；已有草稿时可点「核对最新版本」对照原文。下次在 Web 或飞书机器人以该项目范围对话时，可问「本轮用了第几版工作指令」，助手可按本轮加载的版本和原文回答。清空后会说明清空时的版本。尚未保存过指令、插件已停用时，也会说明各自的状态。新派发的普通项目任务会带上说明。普通任务单独填写的验收标准也会交给执行者，要求逐项报告证据和未能验证的条件。需要严格按原文执行的已批准任务和原生会话恢复沿用已确认内容。清空指令或停用插件后，后续请求不再附加这段说明。



在主对话或项目工作对话点「会话状态」，可查看该会话记录的阶段、最近发言、明确的执行目标和待你决定的事项。切换主对话的项目范围或从具体待办进入时，状态按当前范围读取。也可问助手“这段对话进行到哪了”。多项执行同时进行时，状态窗口不会为整段会话指定一个目标。

在已绑定目录的项目页，或已选定该项目的主对话中，可在顶栏按文件名或相对路径搜索。选择「项目文件」结果会打开该项目的只读代码侧栏。用方向键选中结果后，Enter 打开文件，Ctrl/⌘+Enter 复制 `@相对路径`。文件搜索需要启用「对话历史搜索」插件并连接绑定电脑。达到扫描或结果上限时会提示结果可能不完整。也可以在 Web 项目对话或已配对的项目机器人里问“当前项目里有哪些文件名包含 forecast？”。Web 回复中的「查看文件」可打开正文，飞书回复用相对路径标明文件。

在这两个 Web 输入框里，点「引用文件」，或在行首、空格后输入 `@`，即可选择当前项目的文件。选目录后可继续浏览子目录。用上下键选择，Enter 或 Tab 插入路径，Esc 收起候选。也可把代码侧栏中的文件拖到输入框，替换选中的文字。路径先保存在草稿中，确认后再发送。

在 Web 或已配对的项目机器人里，可以问“请核对 @报表/季度 汇总.md 中的第一项要求”。助手按当前项目路径读取正文。多个文件同名时会先询问，正文被截断时会标明已核对的范围。

在 Agent 页的 CLI 会话中点「分享对话摘录」，可分页选择执行机已经保存的用户发言和助手回复。创建时会在线复核所选原文，再发布确认过的文字快照。执行机离线后，原链接仍可阅读；在「已分享的原生会话」中可管理期限、移除已有消息或撤销分享。新增消息或首次勾选「包含工具记录」时需要执行机在线。预览会列出所选助手回复对应的工具名称和调用状态。记录中只有返回回执时显示「已返回结果」。离线时仍可移除已公开的工具记录。希望读者持续跟进时，可在执行机在线时勾选「自动追加后续消息」。确认开启后，同一执行机、目录和 CLI 会话新增的用户发言和助手正文都会进入分享，无需逐条确认。开启前未选的历史仍然私有。执行机离线时，读者仍可查看已发布的摘录。主人可随时关闭追加并确认更新，原链接继续提供保留的内容。插件停用后重新启用，或会话历史发生改写导致上次追加的位置无法核对时，追加会暂停。重新确认开启后，从当前会话末尾继续。

在 Agent 页导出长会话时，可查看执行机已读取的字节数、总字节数和已解析的公开消息数。完整读取后可预览和下载。文件注明电脑名称和标识，每条用户消息单列。执行者连续输出的正文和公开步骤归在该执行者名下。

启用「对话摘录分享」插件后，在 Web 原对话打开「分享对话摘录」，勾选需要公开的消息，核对正文预览和有效期，再创建链接。读者用能访问工作台的浏览器打开链接即可阅读。链接只在创建后显示一次。在原对话点「修改分享」可增减已公开的消息，预览并确认后，读者通过原链接看到新版。默认沿用原到期时间，也可重新设置。阅读页打开时，自动追加的分享每 15 秒核对一次，静态摘录每 30 秒核对一次，切回页面时立即核对。已有分享可在原对话撤销，到期或撤销后重新打开会显示失效。读者已复制的文字无法收回。如需展示助手调用过哪些工具，勾选「包含工具记录」并核对预览。默认只分享正文。开启后，所选助手回复可显示工具名、调用状态，以及能核实并适合公开的参数或结果摘要。修改已有分享时取消勾选并确认更新，原链接会移除工具记录。附件保持私有。后续消息默认不追加。勾选「自动追加后续消息」并确认后，读者可在原链接看到同一项目和待办范围内新发的 Web 提问及其完成的回复。开启前未选择的消息不会补入。编辑分享时关闭自动追加并确认，可保留预览中已收录的消息。重新开启时从确认时刻继续。达到 100 条或后续消息将使摘录超过 256 KiB 时会暂停追加，主人可在分享列表查看原因。

启用「对话导出」插件后，可在消息下点「复制正文」。主对话和项目回复按 Markdown 标题分节。点击回复里的外部资料链接，会在新标签页打开原地址。点击行内代码即可复制，键盘可用 Enter 或空格。代码块上的「复制代码」保留整段换行。长引用可展开核对原文，生成中的引用完整显示。回复中的 Markdown 表格也可单独点「复制表格」，粘贴到电子表格时保留行列。显示译文时复制译文，切回原文后复制原文，保留 Markdown 和换行。在主对话、项目工作对话或飞书独立对话详情点击「导出对话」，可预览、复制或下载整段对话的 Markdown。预览显示下载文件的字节数。关闭窗口或切换「包含公开工作步骤」会取消旧的导出请求。执行机返回正在读取的一页后，服务端会停止读取后续页。导出原生会话时，同一条回复内的正文与公开工具调用按原顺序排列。下载文件名带浏览器当地日期，正文记录 UTC 导出时间，主对话使用导出时的主助手名称，项目工作对话使用「项目助手」署名。已绑定工作区的项目会附上导出时的电脑标识和目录。独立 CLI 历史也支持导出，执行机须在线并支持读取完整会话。读取已有日志无需启动 CLI。勾选「包含公开工作步骤」可附上已记录的工具名，支持折叠块的 Markdown 阅读器可展开查看；原生会话按调用标识核对回执，有明确成败标记才显示成功或失败；只有回执时显示「已返回结果」。导出文件省略工具参数、原始结果和内部推理。原生会话中的图片以附件标记呈现。

启用「消息收藏」插件后，可在主对话和项目工作对话收藏单条消息。收藏列表跨项目保存。可按标题、发言角色或正文搜索，多词用空格分隔。每次显示 24 条，长消息先显示前 6 行、最多 420 个字符。展开可读完整收藏快照，复制和导出使用已保存的完整快照。取消收藏后，可在当前操作位置点「撤销」恢复原快照。如果另一窗口已重新收藏，则保留现有条目。其他 Web 窗口修改收藏后，当前列表和消息上的收藏标记会同步更新。点「定位到原会话」可打开原消息并查看上下文。原项目归档或原消息删除后仍可阅读收藏快照。每条快照最多保存 4000 个字符，最多收藏 300 条。下载 JSON 可用于恢复。导入时先预览新增数、已有数和剩余空间，再确认合并。恢复的快照保留正文和时间，不关联本机原消息。

在「Agent」的「CLI会话」中选择「查看消息」，可分页查看在线执行机保存的历史，并收藏单条公开消息。从收藏列表查看原文时，系统重新读取该会话并核对消息位置和内容指纹。若日志已改写或执行机离线，已保存的收藏快照仍可阅读。缺少原消息时间时，收藏卡片标明收藏时间。




在顶栏搜索输入 `state:running project:月报 since:7d`，可以查找月报项目最近七天更新且仍在执行的记录。也可点击「筛选执行记录」选择状态、项目、机器、执行器和更新时间。抽屉会显示当前条件匹配的执行记录数。可清除一组或全部条件，已输入的普通关键词会保留；点击「应用筛选」后生效。选择具体项目、机器或执行器时按 ID 精确匹配，例如 `machine:=linux`。应用后可直接修改搜索框中的条件，或点击「保存当前检索」留作下次使用。顶栏也支持以空格分隔的「昨天」「今天」「本周」「最近七天」。前三项按浏览器当地日期计算，本周从周一开始。支持按机器（`machine:`）、执行器（`agent:`）和关键词组合检索。执行标题匹配优先展示；按验收标准、输出、错误或工作树分支找到的执行会显示命中摘录。超过五条时可点「查看全部匹配执行」，从结果打开执行详情。在 Web 或飞书项目对话中也可用验收条件、错误码、输出片段或分支名询问历史执行。可同时指定机器、执行器和时段，按记录中的机器 ID、执行器 ID 和最近更新时间筛选。旧记录缺少机器 ID 时，无法确认当时使用的机器。助手可按执行 ID 核对登记状态和完整记录。Web 回复中的「查看执行」可打开详情，飞书回复用执行 ID 和更新时间标明出处。主对话匹配超过五条时，点击「查看全部主对话消息」可分批查看并定位原文。项目工作对话匹配超过五条消息时，点击「查看全部匹配消息」可以继续翻页，点击消息可定位到原对话。也可在 Web 或飞书项目对话中请助手查找以前的原话。记得原句时可按连续文字查找，只记得大意时可给出几个关键词。关键词须出现在同一条项目消息中，顺序不限；回复时可引用发言角色和原文摘录。追问完整原话或被摘录省略的条件时，助手可按消息 ID 读取同一项目的正文。Web 回复里的「查看原文」可跳回该条消息；飞书回复用项目、发言角色和消息时间标明出处。启用「对话历史搜索」插件后，点击「保存当前检索」为查询命名。下次打开空白的顶栏搜索框，可直接选择列表中的前五项，用当前数据重新检索。按方向键选择，按回车套用。「管理保存的检索」可查看全部条目。可编辑名称和查询、调整顺序，或撤销最近一次删除。其他窗口修改过列表时，刷新后可以继续编辑当前草稿。


「收件箱」展示个人采集与机器人收件。个人消息默认按账号、项目和会话合并；群聊还按已核验的发言人身份区分，不按显示名合并同名人。原始消息独立保存，展开会话可查看来源、归属和历史。后台合并后的事项复用原有待办，零散发言与闲聊不会自动成为人工决策。机器人确认及高级来源操作沿用原流程。

「发件箱」展示系统通知投递与机器人发件，包括正文、目标、待确认、等待发送、发送中、已发送、失败和结果未知等状态。同一投递按关联标识合并展示。页面只读，不会因打开列表或详情而发送、重试消息；结果未知提示先核对实际送达。收发记录随工作台事件更新，空箱显示真实空态。

对话顶部“等你处理”集中审批、需要人回答的提问和飞书行动消息。普通批准一次点击；高风险需要三秒内再确认。提交后显示“已接收，等待结果”，不代表待办完成。输入区留在首屏，Enter 发送、Shift+Enter 换行；请求失败保留草稿，不自动重发。

在「Agent → 高级 → 界面 → 助理卡片示例」可切换六种卡片，查看选择、表单提交、进度更新和文字回退的效果。示例使用合成数据，操作只在当前预览中生效。可在插件配置中启停「助理卡片示例」。

新用户可按四步引导配置 Agent、创建项目、添加记忆和连接渠道，渠道可先跳过。引导根据实际数据更新，不阻止对话。Agent 高级区可以回看进度。作用标签可聚焦、悬停或点击查看说明；单项隐藏和全局关闭只保存在本机。

同一浏览器会记住输入或分享链接中的访问令牌 30 天，刷新和重启服务都可继续使用。

收件箱把可识别群 ID 的消息按已归属项目和群折叠。未归项目的群优先参考同群历史归属，其次匹配群名中的项目名；展开后可逐条确认归属。

工作台使用 wynneceles 的开屏影片（分镜、动作与剪辑），按原比例静音播放。素材限非商业用途，详见[来源及素材许可](https://github.com/wynneceles/ai-boot-animations/blob/main/claude/assets/LICENSE.md)。每次打开或刷新网页，在取得首个快照时自动播放，默认播放全片约 22 秒，不夺焦点、不阻挡操作；点击或按键可关闭。开屏结束或跳过后，约 5.8 秒的第二段视频会静音循环作为背景。站内切换页面会保留背景，关闭工作台开屏插件可停止播放。Agent → 高级 → 界面 → 预览开屏可重播；减少动画偏好下立即结束。

在「Agent → 高级 → 电脑接入与终端」查看在线电脑和真实终端。执行详情“终端”也可打开同一画面。关闭观察不会关闭远端进程；旧终端抽屉中未关联工作台执行的终端只读；独立现场接管使用项目执行页的新入口。关联的交互执行需先点“接管输入”才能发送文本，任务执行只允许中断。已结束执行不提供写操作，不提供完整历史回放。工作区、标签页管理、远程安装和文件编辑尚未接入 Web。

终端可用与 CLI 在 PATH 上只代表依赖存在，不代表 CLI 已登录。任务模式使用 Codex JSON / Claude Code stream-json 原生结束信号和进程退出码确认结果，并自动回送主对话；断线后读取原结果，不重新启动。交互模式没有可靠的任务结束证据时保持进行中或结果未知，不根据终端空闲伪造完成。执行机默认目录为代理启动目录，也可通过知识和显式参数指定项目目录。

在「电脑上的项目文件夹」点「刷新目录」可重新读取候选。点「隐藏」只对当前浏览器生效。点「显示已隐藏」后可逐项恢复显示。添加文件夹面板沿用相同的显示偏好。

项目「执行」上方的「项目现场终端」按绑定电脑和同一真实目录展示独立启动的 CLI。点「打开现场」连接原终端，默认只读；点「接管输入」后可直接在终端中操作，点「停止接管」返回观察。点「最近输出」读取宿主当前可提供的最多300行，不代表完整历史。关闭抽屉只释放观察或控制连接，不停止原 CLI，也不发起新执行或恢复线程。现场状态来自宿主，不表示业务验收完成。连接丢失、终端被替换或目录改变后，旧输入连接不可复用，需重新观察。执行机代理需继承终端宿主连接环境，缺失时页面明确提示。

## 独立 CLI 历史与原生恢复

进入「Agent → CLI会话」只读发现已连接电脑的 Codex/Claude 历史，支持电脑、项目及关键词筛选。显示全部已返回记录；达到读取上限时提示截断。元数据时间可能是会话创建或索引更新，文件记录更新也不等于进程仍在运行；历史记录不授予终端写权限。主 Agent 可用只读 `agent_sessions` 查询，事项机器人只看到已关联该事项的原生线程。自动列表复用既有 worktree/临时目录过滤；手动指定的精确线程验证仍允许已绑定目录。

点「申请恢复」，确认原终端已停止，填写继续目标、验收条件和预计时长。申请只创建审批，未启动进程；去「等你处理」核对原生线程、电脑、目录和参数后批准，才创建新的执行尝试。它续用历史线程，不附着原终端，不重派旧尝试，不用新线程作为失败回退。审批时重查目录/身份/项目归属和代理能力；同标识请求不得改内容，网络结果未知时仅只读核对，不自动重发。原有 unknown 记录保留；明确批准的新继续请求不能被误称为旧请求自动重试。

旧代理没有新能力时提示升级；机器离线、CLI 不可用或未提供可验证原生恢复能力时不能申请。CLI 在 PATH 上不代表已登录。仅匹配线程 ID 和执行插件声明的原生结果来源才能确认恢复结果；缺证据保持 unknown，返回其他线程时停止本次受管子进程并记录失败。执行结束仍不自动完成待办。

默认适配 Codex、Claude Code；核心不解析厂商事件或拼 CLI 命令。执行插件声明 `nativeResultSources`，处理厂商参数与事件；同步插件需返回不可由展示钩子更改的 `nativeResult` 证据，纯文本“成功”不足以完成恢复。这里提供原生线程恢复，终端宿主重启后的自动恢复描述尚在主线清单中，不能混同为同一能力。

## 飞书渠道

「渠道」按扫码创建、飞书配对、选择项目三步接入。二维码和配对进度读取服务端真实状态；结果未知不会自动重新创建。手动应用凭证、原有连接、多机器人信箱、事件与待发草稿收在“高级”。凭证只保存在服务端私密配置，不返回密钥。

个人消息采集会将「智能纪要助手」发来的纪要文档链接或会议正文加入「记忆 → 设置与队列」，来源标为「会议资料」。整理 Agent 启用后读取资料，提炼会议决定、进展和待跟进事项。飞书文档需要在整理设置中开启受保护来源读取，并使用有权查看原文的账号。可以在队列查看原文档、整理状态和失败原因。整理成功的资料默认存到「记忆 → 个人」，作为未分配项目的会议背景供后续分析检索。「全局」用于工作原则。

个人消息采集直接在「渠道 → 个人消息采集 → 授权飞书账号」操作：点击授权、用飞书扫描二维码并确认、等待页面显示账号，再点击「开启采集」。也可打开同一授权链接完成确认。扫码后由服务自动核验账号和读取权限；授权本身不会开启采集。不需要用户填写配置名称、App ID、密钥或运行命令。

在个人消息采集设置中开启「编辑历史」后，工作台可记录当前账号采集到的飞书文本消息旧版本。在对应的原始收件中查看旧正文及被替换的时间。也可在 Web 主对话或已配对的主人私聊中询问某条收件改过什么。每条消息最多保留最近 50 个实际采集到的旧版本。关闭此设置会清除当前账号保存的编辑历史，重新开启后从下一次采集开始记录。

在个人飞书的原始收件详情打开「置顶消息」，可查看该会话的置顶列表和来源。打开话题中的置顶时，详情显示原消息所在话题，可继续加载回复。在主人对话中也可按置顶消息追问话题讨论。只有打开列表或在主人对话中明确要求查看时才读取。置顶当前消息、取消已有置顶均需在 Web 确认。飞书写入超时后，请刷新列表核对当前状态。飞书应用和该账号的用户授权需要允许置顶写入，可按需授予 `im:message.pins:write_only`；仅查看可沿用采集所需的 `im:message:readonly`。

在原始收件详情查看「表情回应」，可浏览回应者、添加表情或撤回自己的回应。修改回应需要当前飞书账号具备 `im:message.reactions:write_only` 或等效授权。Web 主对话和配对主人私聊可按收件编号查询回应。列表有下一页时，当前显示的数量只覆盖已加载的记录。

服务自动使用已有飞书应用配置；没有配置时，可复用工作台已连接的应用并在内部准备命名配置。完全没有应用时，页面引导到现有扫码接入流程；应用缺少权限时，提供该应用的权限设置链接供管理员处理，随后点击「重新授权」。`lark-cli` 是服务端连接组件，缺失时明确报告，不模拟成功。演示模式不访问真实飞书配置，不生成真实授权。

采集独立于机器人长连接，空闲时每两分钟检查新消息；首次最多读取最近24小时。若已有“重新开始”的起点，只读起点之后的消息，不擅自回填旧历史。每次最多读取3页搜索结果，每页最多50条；私聊分页未完成时先继续私聊。群聊最低优先级，只从按最近活跃时间排序的前100个群会话中选择未解散、明确未免打扰的群，不遍历全部历史群。群内明确@的路线先于普通群消息。

每批入箱成功后保存断点。私聊进度可独立向前，群读取保持原时间范围；重启继续未完成路线。群名单或群读取失败时延后重试，不拖停私聊。页面分别展示私聊最近读到、完整读取水位、当前是否读取中和本批条数；0条只表示本批没有可入箱消息。授权凭证由CLI保管；账号绑定和采集断点仅保存在服务端私密文件，公开状态不含配置名或分页令牌。重启重新核验账号；停止后迟到结果不入箱。此功能不保证全部群或永久历史的完整存档，也不会以user身份代发消息。

**个人消息来源可单独选择。** 在「渠道」打开 CLI 个人消息采集，或在旁边的「飞书网页版网关」管理插件。两个开关独立，重启后沿用选择。同一账号建议只开一种。两种接口返回的账号和消息标识可能不同，同时开启可能重复收件。CLI 适合需要群聊筛选或个人 `/ai` 草稿的场景。

打开「渠道 → 飞书网页版网关 → 配置网关」。地址默认填入工作台服务端本机的 `http://127.0.0.1:4310`。同机部署时使用默认地址，远端网关填写 HTTPS 根地址。此地址需要有兼容的网关服务监听。填写网关签发的访问令牌后保存，已启用的插件会按新配置重连。原有部署仍可通过 `SUPER_MARIO_FEISHU_WEB_BASE_URL`、`SUPER_MARIO_FEISHU_WEB_TOKEN` 提供初始值。在渠道页点击「扫码登录」，用手机飞书确认后查看连接状态与最近入箱时间。登录和工作台采集开关独立。扫码成功后，渠道页会自动刷新采集连接状态；第一次同步可能需要约 15 秒。工作台在后台每 15 秒读取网关的 `/api/lark-avatar/status`、`config` 和 `inbox`，关闭工作台页面后仍可采集。

工作台同步只读取网关收件快照。网关监听推送并补拉历史，后台采集不点击聊天窗口，也不主动发送已读回执。网页版目前接收其他人发来的私聊，按账号隔离并按会话整理。网关近一页收件最多 60 条，密集到达或长时间离线可能漏收。网关未提供可靠的群折叠状态，因此群聊和群话题暂时跳过；此通道仅收件。

采集错误会区分请求参数、权限不足、授权过期、限流和超时。参数错误不需要重新授权；例如飞书 `99992402` 表示参数校验失败，应由连接程序修复。消息搜索起点使用到秒的 RFC 3339，不传毫秒。

高级区保留旧版手动配置与独立采集开关，供已有集成使用；新扫码流程不依赖旧版连接的启用状态。

消息分拣与确认逻辑不变：同一话题聚合，确认带版本，转待办不重复创建。需要人决定的内容出现在对话顶部，待办在项目中推进。机器人正常回复与主动发送分别记录，不用读取成功冒充发送成功。

启动时仍支持仓库外配置 `SUPER_MARIO_FEISHU_ENABLED=1`、`SUPER_MARIO_FEISHU_APP_ID`、`SUPER_MARIO_FEISHU_APP_SECRET` 和可选 `SUPER_MARIO_FEISHU_USER_PROFILE`。真实配置不要提交。

## 审批与自动跟进

审批绑定预览和版本；编辑建议后旧版本不可批准。派发受理、外部结果、待办验收分别显示。网络中断或结果未知不自动重试；服务重启后的未知动作先核对实际结果。

在 Web 或飞书的主对话、项目对话中，可让助手提出包含 1–8 项任务的计划。打开「等你处理」可核对各项的完成标准、预计分钟和估时来源，再决定是否开始。部分派发失败时保留已受理的执行记录。

计划未指定分钟数时，工作台优先采用同项目、同类任务最近 90 天内已验收样本的实际执行耗时。至少需要 5 个有效样本，最多取最近 32 个的中位数；样本不足时采用默认 60 分钟。手动指定的时长优先。计划派工到达预计时间且仍在运行时，后台督办会查证进度和交付证据。单改验收标准保留本次预计复核时间，修改预计分钟则从修订时重新计时。待办详情的「验收标准变更」可查看该轮计划预计复核时间。计划执行取得可信完成回执后，可在执行详情、关联待办中或通过 Web 与飞书助手核对首次回执时间、实际用时和相对首派预计的差额。实际用时从派工起算，按分钟向上取整，最少 1 分钟。修改预计时长只影响后续督办，首派对比值保留。主人是否已验收可以查该轮的验收记录。

「Agent → 自动处理」提供保守、平衡、少打扰三种预设。应用前显示差异。保守与默认配置逐字段相同；平衡只自动处理普通提问；少打扰要求明确的受信工作目录和风险确认，可能允许修改或删除。不会根据文本推断操作只读。自定义规则用项目、执行者和目录选择器，放宽审批标红并在保存前确认。近七天命中次数来自真实处理记录。

「Agent → 自动跟进」配置合批和跟进间隔，查看简报与提醒。模型失败后显示暂停；核对配置后点“恢复自动跟进”。暂停事实跨服务重启保留。普通主动通知仍需已有发送授权。内部只读简报绑定已配对主人后自动投递，不逐条申请批准；更换账号或主人后旧发送失效。

## 事件、调度与通知发件

在「Agent → 高级 → 后台事件与发件箱」查看后台状态：失败投递可显式重试；未知投递必须先核实是否已经执行，再选择标记完成或确认未执行后重试。页面同时显示事件正文、尝试次数、因果链和订阅身份。

后台调度支持一次、固定间隔及带 IANA 时区的五段 cron，间隔至少 10 秒。默认每日简报为 Asia/Shanghai 09:00/18:00。服务端先按持久记录汇总，分别列出等待执行、进行中、结果未知和已取消的任务。主模型可用时再整理简报，模型不可用或超时则使用原始汇总。早报按计划时间和工作台时区核对当天日程，并按项目列出仍未完成的逾期待办和当天剩余到期的待办，包括近期未更新的事项。页面可暂停、恢复和取消；修改时间或时区用调度 API，必须带当前版本。旧版本投递与发件会在执行前跳过。

主动通知默认不获发送授权。可以逐项审批，或明确为某个发布者开启「可通知我」，此授权只允许发给已配对的本人。其他会话仍需逐项审批。发送超时和中断记为未知；只有确定未发送才可换新尝试。飞书原请求的执行结果沿原配对身份回送，不能借此给其他人发消息。

后台督办按每轮执行核对用户验收记录。待办重开或验收后的执行证据发生变化时，督办会收到对应状态。

督办模型失败后会显示「已暂停」与最近原因。核对配置后点击「恢复自动跟进」。暂停状态跨服务重启保留，页面不会只凭模型 available 显示正在运行。

插件可贡献 `event_subscriptions` 并使用 `context.eventbox`、`context.schedule`、`context.outbox`；接口标 experimental。声明事件处理的 `effects` 为 none、ledger 或 direct，并按权限使用宿主 API。停用保留积压 7 天；显式清理会取消未开始的投递、计划和未发送通知，保留已发送及未知记录。事件和终态默认保留 30 天，可通过 eventbox settings API 调整；failed/unknown 不自动删除。普通通知总线独立保留 30 天，since 为每页最多 1000 条的数字游标。

安装包的 `dist/plugins/examples/change-watch/` 和 `approval-followup/` 提供两个可复制的插件目录，分别验证无变化不调用模型、确认后持久接续。插件调用 `core.agent.ask` 默认拒绝；需要显式的用户授权与每日调用上限。没有自动启用这两个示例或真实外发。

## 自定义插件

将插件放在 `<数据目录>/extensions/<插件目录>/`，重启服务后加载。目录包含 `super-mario.extension.json` 与 JS 入口，例如：

```json
{"id":"sample","version":"1.0.0","apiVersion":1,"main":"index.mjs","config":{}}
```

```js
export default {
  id: 'sample', name: '示例', capabilities: ['sample.read'],
  activate(context) {
    context.contribute('tools', 'sample_read', {
      name: 'sample_read', description: '读取示例状态',
      parameters: {type: 'object', properties: {}, additionalProperties: false},
      async execute() { return {ready: true}; }
    });
  }
};
```

源码插件使用 `packages/plugin-sdk/` 的接口，安装包的 TypeScript 插件可从 `super-mario/plugin-sdk` 导入类型。依赖写在 manifest 的 `dependencies` 中；资源使用 `contribute`、`onEvent`、`defer` 登记，停用时统一释放。坏插件显示失败，其余能力继续运行。当前是可信插件同进程执行，没有进程沙箱，也不提供代码热替换。

前端展示通过同一 `context.contribute('web_extensions', id, value)` 注册。当前最小实现支持 `{slot:'startup', renderer:'brand-splash', title, subtitle, durationMs}`；声明时 `durationMs` 为 600–5000 毫秒，省略时播放至片尾。服务端只把启用中的贡献放入快照，浏览器选择已知渲染器并负责卸载。该扩展点支持声明式开屏，不是任意前端 JavaScript 或自定义页面加载器。

自定义扩展点须在清单 `extensionPoints` 中声明 `<插件ID>.<名称>` 和 `version:1`，消费者声明提供者依赖。可调用行为使用 `provide/use` 的 JSON 服务；`hook` 与 `wrap` 统一登记和清理。显式 `permissions` 只允许清单授予的 SDK 调用，旧插件不声明时仍是可信本地模式。开发时运行 `npm run lint:plugins`，系统及第三方插件均禁止导入核心内部实现。完整接口与权限表见 [架构第 5 节](architecture.md#5-插件模型)。

在「Agent → 高级 → 插件文件」可暂存已打包单文件 ESM，展开查看完整源码，确认版本及 SHA256，再单独点击加载。源代码或版本变化需要重新确认；未确认或哈希不符不会执行。加载超时或结果未知时先核查执行机状态，不自动重试。执行机重启不自动加载历史代码。确认的代码拥有 Node 进程权限，这不是恶意代码沙箱，也不提供依赖下载或插件市场。

## 数据与排错

- SQLite：`workbench.sqlite`，保存待办、消息、执行、插件设置和事件。
- 知识：`plugins/knowledge-local/knowledge/*.md`，文件为事实源，读取时更新索引。
- 连接配置：`integrations.json`，包含私密凭证；执行机数据目录另有 `executor-sessions.json`。备份同样需要保护。
- CLI 原生结果：执行机 `task-results/`，包括任务配置与结果；包含工作内容，按私有数据保存。
- 外部动作：数据库 `effects` 集合；已发送但未确认的动作不会自动重放。
- pi：`pi/`，独立认证和会话目录，不读取用户项目的插件与指令。
- 启动独立测试实例时，同时使用临时数据目录和空闲端口。备份前先停止服务端及所有写入同一数据目录的进程。
- 插件失败可在 Web 查看原因，修正后重新启用；停用不会撤回已发生的外部动作。
- 中断时未确认的执行记为“结果未知”，不自动重派。执行结束不会自动完成待办。

**离线备份与恢复**

在保存服务端数据的机器上执行。先停止写入，确认备份文件所在目录有足够空间。以下命令使用新的备份文件名和恢复目录名。

```sh
super-mario backup create --data-dir ~/.super-mario --output ~/workbench-backup.zip
super-mario backup verify ~/workbench-backup.zip
super-mario backup restore ~/workbench-backup.zip --data-dir ~/workbench-restored
```

创建范围是指定的数据目录，包括 SQLite、知识原文、聊天附件以及保存在目录里的凭据。备份包是未加密的私有文件。外部环境变量、远程执行机和项目工作目录需分别备份。目录内遇到符号链接或特殊文件会报告失败，可先核对这些文件的实际归属。

校验逐项核对文件清单、大小和 SHA-256。需要确认覆盖范围时，执行 `super-mario backup inspect <备份包>` 可同时查看数据库是否存在，以及知识正文和聊天附件的文件数。请从可信来源取得备份包。恢复只接受尚不存在的目录，发布前会检查 SQLite 数据库。命令完成后不会启动服务或连接飞书，可先核对资料，再决定何时使用恢复目录。


## 多机器人与事件信箱

在「渠道 → 高级 → 飞书机器人与事件信箱」添加机器人，或从项目卡片进入「项目机器人与信箱」。支持手动凭证和扫码创建，凭证仅保存在服务端私密文件。扫码会话可以复用；自动创建、权限配置和发布后必须回读核验，未核验保持禁用，结果未知不自动重试。

机器人可绑定全局、项目、事项或未标记范围。首次扫码用户能由新应用验证时，直接私聊即可；无法验证或手动接入时，先向机器人发送界面的短期配对码。默认消息入口仍是已绑定用户的私聊。可在「渠道 → 高级：手动接入、信箱与事件 → 编辑机器人」显式配置群；普通群协作只处理配置过的群。群内不能配对，须先通过私聊验证主人。

主对话里有一张默认等待答复的问题卡时，可以在卡片中提交答案，也可以直接在同一对话里发新消息。直接发言会撤回原提问，助手按这条新消息继续。Web 可从原提问通知回看撤回原因。主人在飞书私聊中发新消息时也遵循这个规则。其他对话的提问、执行机问题和审批仍各自在原入口处理。

如果你明确说「这个我稍后再选」，助手可发出一张稍后回答的问题卡。你可以在原对话继续聊别的事，之后回到卡片回答或关闭。答案会送回提问的会话。无人发言且提问到期时会转成待办；期间你已在原会话发言却未答卡，到期只通知原会话。工作台同时最多保留 20 张尚未回报结果的稍后提问。权限和外发审批仍需明确确认。

普通提问已等满两分钟，同一会话还有协作回报或系统消息排队时，工作台可把原卡转为「稍后回答」。原选项、已填写的内容和答复入口继续可用。已经处理完的消息不会触发转换。后续消息按自己的内容处理，不能替主人作决定。

一张问题卡最多有四道题。单选题可选一项，多选题可同时选多项，也可以逐题填写自己的答案。Web 和飞书都在提交时核对每道题与原卡版本，整张卡回答一次。已失效的卡不能覆盖先前提交的答案。飞书原生表单容量不足时，会提示到 Web 回答；已配置工作台访问地址时，按钮可直接打开原问题。

选项旁的「推荐」表示助手的建议，你仍可选其他项。带决定期限的问题会显示截止时间和到期处理方式。如果每项决定均可撤回，无人作答时系统会记录推荐选择，并把来源标为系统默认。删除、对外发送、付款或变更生产等决定到期只提醒一次，仍可在原卡选择。稍后卡等待期间你已在原对话另发消息时，到期不代选。

未设置决定期限的普通问题在对话里过期后，会生成一项待办。打开详情里的「超时提问」可查看原文和提问时间。文字提问可提交答案，或在该待办登记一条主人决定。多题卡请逐题回答并提交。原会话受理后待办完成。只勾选完成会告诉原会话这项提问已关闭，没有答案。执行机提问和审批沿用原入口。

为运行中的交互执行设置限时决定时，逐题填写推荐项，并明确整个决定是否可撤回。在 Web 执行详情的「等待你」或飞书的执行会话状态卡里，可以查看每题的推荐理由、其他选项、决定截止时间和到期处理方式。默认选择只送向提问时绑定的原执行会话。执行历史区分系统到期选择和主人回答；送达结果未知时请核对原执行记录。在执行问题卡点「你来定」可以把本轮选择交给督办。可撤回且仅影响私有工作的选择，会记录督办采用的选项、依据和执行机回执。不可撤回、对他人可见或影响范围未注明时，原卡会列出推荐供你确认。选择「否，我自己选」后仍可逐题回答。

发现原题偏离目标时，点「这不是我要的」退回督办。工作台暂停该执行的自动跟进，保留执行进程和原卡记录。督办核对这次偏差与下一步后解除暂停；模型不可用或复核依据已变化时继续暂停。

在原卡点「先告诉我背景」，可以先看执行目标、提问原因与选项的差别。旧截止时间停止代选，之后仍可手动回答原卡。不可逆决定到期后仍可从原卡回答。在提问所在的 Web 对话或飞书主人私聊中，若只有一道待答执行题，可以直接发送选项全文。多题或多张卡同时待答时，可以点原卡，也可以发送「回答提问 <卡号> v<版本>」，随后逐行填写「1. 原选项」，多选时重复该题号。

早晚简报在待办生成后的七天内展示尚未结案的问题。过了七天仍可从待办详情回答，也可以在 Web 或飞书询问助手「还有哪些事等我决定」，从返回的待办链接打开。已结案的问题退出提醒。

编辑全局机器人时可调整「待决定提醒等待时长」。已配对的主人收到可直接回答的问题卡后，默认等待 60 分钟。到期仍待回答时，机器人回复原卡一次。设为 0 可关闭提醒。「Agent → 自动跟进 → 简报与离场通知」可设置免打扰时段，按简报时区生效，支持跨午夜。时段结束后会重新检查问题是否仍可回答。主对话提问默认等候两小时，已配置的用户答复期限优先。提醒只在提问和原卡操作权限均有效时发送。普通飞书表单操作权限为 24 小时。

机器人可以选绑一个现有执行者。该绑定约束直接派发、拆分计划和延迟批准；执行者离线会明确失败，不会悄悄换执行者。未绑定或未配置机器人不影响原有执行路径。机器人是渠道身份，不另建业务 Agent。

「群协作」按群设置会话标识、是否必须 @ 自身、允许发起任务的成员。成员留空只允许已验证主人，不能用“任意 @”或显示名代替机器人真实身份。可配置群也不等于授予任意主动外发；手动草稿仍先进入待确认发件箱。对原消息的回复保留群和话题，停用、改绑或撤销成员后旧动作失效。真实租户仍需按平台要求开通群消息事件和权限，本轮没有代为申请或验证。

主人可以在群里发送 `/topics` 或 `/话题群` 登记话题群，用 `/topics home` 指定主群，用 `/topics off` 移除。Web「Agent → 主 Agent 的飞书机器人 → 话题群管理」也能登记、命名或移除群，并设置是否要求主人实际 @ 本机器人。普通登记的首个群可作为默认主群；要求点名的新登记群需要显式选为主群。最多登记 50 个群。

需要分阶段接手一项工作时，在原待办详情选择「创建续办」，填写下一阶段标题和交接说明。原待办保持自己的完成状态。Web 或飞书项目助手也可按明确指定的前序待办登记下一阶段。打开待办详情可回看直接前序，也可逐个打开后续分支。「续办历程」列出同一条工作线的各阶段、分支和实际完成时间，可从任一阶段打开其他阶段。项目助手可查完整历程，事项机器人只处理自己的待办。交给主助手或派发新执行时，交接提示会引用同项目这条续办链中仍生效的决定，标出原待办和来源。移入其他项目会断开跨项目的续办关系。

在待办详情展开「交办依据」，可核对首次登记的标题和备注。飞书群和话题中的主人交办会分别保存命令正文和引用材料。经核实的主人消息摘录仅向 Web 主人及对应来源会话展示。旧待办缺少首次登记记录时会标为重建。各轮验收标准按派工时间排列，可打开来源执行核对实际结果。续办只列本项和直接前序链的标准。

展开某轮执行的验收标准，可查看首派标准、当前标准和每次修改的原因。执行仍在运行且待办未完成时，主人可以修改标准和预计分钟数。另一个窗口已经保存时，先核对最新版本，再决定是否沿用草稿。也可以在 Web 或已配对的飞书主人私聊请助手查询、讨论变更。确认时单独发送「把执行 <执行 ID> 的验收标准改为 <完整新标准>」，可另起一行填写「原因：…」和「预计分钟：…」。保存后工作台按新标准验收。督办从该版本生效时重新计时，并关闭上一版的超时提醒。普通执行输出不会延长时限。需要执行者立即调整工作时，仍需通过原会话传达。

在 Web「待办详情 → 飞书话题」选择已配对的全局机器人和已登记群，填写目标话题 ID，确认后即可绑定。已有绑定可修改标题、更换话题或解除绑定。解除会保留历史决定。每项待办最多关联一个话题，每个已登记话题只能对应一项待办。已认证的工作台客户端也可通过 `PUT /api/v1/todos/:id/thread` 将已有待办关联到指定机器人的已登记群话题。传入 `channel: "feishu"`、`botId`、`chatId`、`threadId` 和可选 `title`。首次绑定传 `expectedVersion: null`，换绑或解除时使用 GET 读到的当前版本。绑定操作本身不会发送群消息。主人在新话题的首条有效发言会成为待办决定，后续通知据此回复。项目待办仍在 Web 项目中办理。

需要由执行会话绑定时，先让主人在已登记群的目标话题发言。派工说明中按 `oc_群标识 / omt_话题标识` 成对填写真实 ID，再在待办详情指定负责会话。本地启动的 Codex 会话可通过 `todo_bind_thread` 登记该话题或更新标题。共享远端 Codex 会话使用 Web 管理绑定。换绑或解除绑定由主人在 Web 操作。负责会话可用 `todo_decisions` 重读当前生效的决定。主人追加、撤回决定或交接负责会话后，下次读取即按新状态返回。执行会话用 `todo_decision_add` 记录影响后续工作的取舍，可写问题、选择和理由。修订时指定被替代的执行决定。Web 待办详情保留历史，区分执行者的取舍和主人的决定；主人可撤回记录。

主人在已登记群开新话题，或在已有未绑定话题发送 `/ai 任务`，会建立 Web 待办。同话题的后续发言作为该待办的决定，助手回复在原话题下。严格点名的群需在发言或登记命令中实际 @ 本机器人。直接在话题里创建的待办，在 Web 确认完成后，机器人会在原话题通知成员。主人在 Web 待办详情新增决定后，机器人会在话题回复决定数量。状态通知跟随主人在同一话题的最近一次有效发言。每个机器人配对保留最近 200 个话题的回复位置，保留期为 30 天。消息撤回或回复位置过期后，主人再次在话题发言即可恢复通知。回报预览仍回复任务承接消息。外部群任务转入主群话题后，数量通知发到主群话题。首次等待 3 秒合并，每个待办每分钟最多通知一次，每批最多计入 50 项。负责会话的待处理提醒和已核实的任务执行结束提醒也在同一批合并。群内只提示状态。主人可到 Web「等你处理」查看请求和权限详情。卡片已关联待办时，点击待办名称可查看上下文并回答。任务执行结束后仍须验收待办。话题成员看不到 Web 决定原文。配置可公开访问的 `SUPER_MARIO_WEB_URL` 后，完成和决定通知会附原待办链接。链接不带访问令牌，打开详情需要已有的 Web 访问权限。移除群后重新登记会建立新的话题绑定。

待办指定负责会话后，主人在原话题追加的决定会进入 Web「等你处理」。核对原文和目标会话后批准，执行机才会向该会话写入原文。拒绝、改派或撤销登记后，旧审批无法写入。原话题会收到输入的送达状态。执行机支持逐条核对时，会在本机保存输入编号和原文指纹；回执编号不匹配时显示送达未知，不会再次写入。判断工作是否完成，还需查看该次执行的结果。若在 Web 将待办转入项目，后续决定请在该项目中处理。

要让交互会话的最终答复回到话题，可在 Linux 执行机上将 `SUPER_MARIO_CODEX_SOCKET` 指向已有 Codex app-server 的 Unix 套接字，再启动执行机代理。使用执行机用户拥有的私有目录和套接字，例如目录权限 `0700`、套接字权限 `0600`。在 Web「Agent → CLI会话 → 申请恢复」选中该原生会话、关联待办并选择「交互会话」。确认原终端已停止后提交恢复审批。恢复成功后，在 Web「编辑待办 → 负责会话」选择这次恢复的会话。

后续话题输入的 Web 审批会说明是否将答复公开到原话题。支持回传的执行机核对原生轮次编号、主人输入和最终正文，机器人再回复原消息。输入回执先到；执行中或暂时离线时，工作台会定时复核。长答复分段发送，每段取得飞书消息编号后才发送下一段。普通终端仍提供输入送达状态。

在普通飞书群里实际 @ 已配对的全局机器人，输入 `/ai 检查本周发布清单`，会在 Web「待办」建立一项任务。已设置主话题群时，机器人在主群另开话题办理；没有主群时，机器人私聊你并附上待办编号。主群开题失败时可到 Web 核对已建待办。回复他人的消息时，机器人能读取的被引正文会标为背景。单独发送 `/ai` 会在原消息下收到用法提示。重复推送同一消息沿用原待办。

在 Web 待办详情里可填写「群内回报结论」，确认完成后机器人按该结论回原群。留空时只回报待办已完成。默认先在办理的话题或主人私聊预览，10 分钟后回复当初提及机器人的那条群消息。引用私聊承接消息或预览回复 `/noreply` 可以取消。在全局机器人设置中可将等待时间改为 0 至 60 分钟；0 表示直接回报。外群任务由主话题承接时，主话题会在预览中看到完成结果。设为即时回报或在完成前已取消原群回报时，机器人会在主话题单独通知待办已完成。已经预览的回报沿用告知主人的期限。送达结果未知时不会自动重发。

要请机器人读群，在「渠道 → 高级：手动接入、信箱与事件」编辑已配对的全局机器人，勾选「允许已配对主人在群内读群」并保存。此项默认关闭，适用于该机器人所在的所有群，独立于「群协作」的群和成员白名单。手动接入时请订阅 `im.message.recalled_v1`，这样服务能在触发消息撤回后停止后续处理。只有已配对主人能发起读群。请在目标群的消息输入框中实际 @ 这台机器人，随后输入 `/读群 总结本群的待办`，或使用英文命令 `/read`。回复出现在发起消息下，对群成员可见。

在「渠道」连接个人飞书账号时，使用与机器人相同的飞书应用和已配对主人的身份。默认读取最近 40 条群消息，并补充触发话题的回复。可以在任务中指定时间或消息范围，群消息与话题回复合计最多读取 500 条。机器人会按任务选择图片和附件，单个资源最多 50 MiB，合计最多 200 MiB，最多 20 张图片。回答会说明未能读取的范围或资料。可读取常见图片、UTF-8 文本、CSV、PDF 或 DOCX 正文及 XLSX 单元格。ZIP 只列目录。下载依赖 Linux 的 `prlimit` 和 `lark-cli`，文件只在本次读取的临时目录中处理，结束后清理。

在 Web「Agent → 主 Agent 的飞书机器人」点对应机器人的「读群记录」，可按时间回看当前配对主人的任务和群内答复。记录区分处理中、已送达、失败、送达结果未知和已撤回。分段回复只展示飞书已确认送达的正文。点「加载更早记录」可继续向前翻阅。关闭读群开关后仍可查看本次配对的历史。断线时抽屉清空记录，重连后重新读取。

主人私聊和每个飞书群分别续接自己的模型对话，服务重启后仍可继续。重新配对会开启新的模型对话。升级时，旧混合记录中只有能核对来源的用户发言和最终回答可以恢复。

「Agent协作」选择来源机器人、双向允许的目标机器人和请求文本，可选双方共同配置的群；空群表示仅内部协作。请求经目标信箱确认策略处理，界面显示入箱不代表执行或平台送达成功。A2A使用内部事件/信箱，不依赖飞书转发机器人间消息；平台机器人消息仍忽略。内部因果链最多8个身份、24小时有效，重复请求同标识不得改内容，unknown不自动重发。

主 Agent 可以用 `bot_handoff` 交给已授权同伴；服务端从当前会话确定来源、父信件及请求标识，不能冒用其他机器人。原群发起且双方已配置该群时继承原群/话题。目标回答和原生执行结果按消息标识回流一次，以只读资料进入发起会话，不授予再次委派或写入权限；原入口存在时总结可走原入口，没有入口时不猜收件人。执行结果、待办验收、回报入会话和真实外发送达分别记录。

主 Agent 实时快照补充执行者、机器、会话、原生结果来源和待决策归属。只汇总已接入事实；未上报独立CLI不视为没有工作，适配器可用也不代表CLI已登录。


- 默认入站消息等待确认；关闭此设置后，已明确范围的消息自动受理。未标记消息始终先分配到全局、项目或事项，再确认处理。
- 主动发送先保存发件草稿，再确认具体版本。正常回复和收件回执走同一事件信箱，不再次要求批准。当前只向该机器人已配对会话发送。
- 信箱中的完成表示本次输入已受理或本次发送返回；外部执行是否完成、待办是否验收仍分别记录。
- 改绑、停用、归档会阻止旧消息继续路由；已启动的外部任务不会因此自动终止，需要在执行页单独中断。
- 发送未知和服务中断不会自动重发。修改范围后必须确认新版本，不能复用旧确认。

在「Agent → 主 Agent 的飞书机器人」可查看全局机器人的连接及配对状态，点击「配置机器人」打开已有全局机器人；首次使用时进入扫码向导。版本提交后工作台会短暂轮询发布状态。若核验仍未通过，打开该机器人可查看配置链接；在飞书确认发布后可启用连接，连接建立后按页面提示配对。已有机器人也可在渠道页绑定为全局。

### 飞书总指挥群

打开「Agent → 飞书总指挥群」，点「创建总指挥群」。工作台用已配对的全局机器人建私有群，邀请主人和当前已启用、绑定有效项目的机器人。多个全局机器人时先选主机器人。以后有新项目机器人，点「同步成员」加入原群。页面逐个显示入群结果，飞书要求审批时需等审批通过。

在群里发任务时，@ 一个已配对的项目机器人即可指定项目。也可以只 @ 总指挥，首行写「项目：项目全名」，下一行写原任务。全名唯一匹配已入群的项目机器人时直接路由；未匹配或重名会要求重新指定。没有点名或指定全名时，主 Agent 根据消息和候选项目的名称、简介选择项目。归属不清时，带上原任务并 @ 负责项目的机器人重新发送。需要确认的项目会先收到待确认任务。要接收无人 @ 的群消息，主机器人需在飞书开通接收群内全部消息的权限并发布；项目机器人可以保留只接收 @ 的权限。


Web 和飞书对话每轮读取当前范围内最近 12 条执行的验收状态。重开待办后，再问进展时可看到最新状态；询问更早的轮次时，助手可按待办查询验收历史。项目和事项机器人使用独立会话；工具按绑定范围校验读写。主 Agent 可以用 `bots_list`、`mailboxes_list` 查询全局进展，用 `mailbox_propose` 提交待确认发件，不能代替用户确认。飞书租户的真实扫码、审批和消息收发仍需在相应账号环境验证；本地回归不代表这些外部步骤已经通过。

要从飞书询问“所有项目在做什么、哪些工作等我决定”，使用绑定“全局”的机器人。每轮模型执行前会自动读取共享工作快照，包含项目与记忆摘要、未完成待办、执行状态/结果、待确认决定、电脑在线状态；并不要求这些工作来自当前机器人。快照有容量上限，会标出总数与遗漏数，详情由现有只读工具查询。项目/事项机器人继续只看绑定范围；未接入或未上报的 CLI 不在快照中。各入口原始聊天历史仍独立，只有聊天、没有落入任务/记忆的决定不会自动共享。执行完成不代表待办验收，机器人消息草稿仍需原有授权。

## 代码浏览、离场通知与简报（2026-11-17）

主对话先选择项目，再点“查看代码”。项目持续对话直接点“查看代码”。目录与文件来自项目绑定电脑，电脑离线或代理缺少 `workspace.code` 能力时显示原因，不回落到服务端路径。只支持 UTF-8 普通文本，单文件不超过 256 KiB；隐藏凭证及仓库内部目录，拒绝越界软链接。Git diff 展示相对 HEAD 的已跟踪文件变化；未跟踪文件用“文本”查看。

“Agent → 自动跟进 → 简报与离场通知设置”可修改早晚时间、IANA 时区、间隔小时数、同日活动时段和离场通知偏好。间隔默认关闭；启用才创建隔离/当前所连接实例的间隔任务，关闭会暂停原任务，再启用复用原任务。仅修改相关既有调度，不替换自定义任务、不恢复用户手动暂停的早晚任务。活动时段不跨午夜；结束不包含在时段内。

任一页面标签可见且聚焦即视为在场；后台标签不能清除前台标签的租约。心跳每 15 秒发送，失联最多 45 秒后按离场处理。离场通知覆盖最终对话回答、执行结果及待决定消息。路由按事项、项目、全局顺序选择已连接配对的机器人；缺少目标在设置中显示积压。进入发件箱后沿用原授权和内容版本审批，unknown 不自动重发。机器人改绑会阻止旧通知。返回 Web 或关闭离场通知会取消尚未发送的离场积压，sending/sent/unknown 记录保持原状态。私密配对目标不放回公开机器人列表。

简报按上次生成截止到本次调度时间的 `(from,to]` 窗口汇总，首次早间回看 15 小时、晚间 9 小时、间隔回看配置间隔。各类简报共用生成游标以减少重复；待决定包括此前积压。执行结束与待办验收完成分别展示。摘要不是历史状态回放；长列表在通知中保留前 20 条并明确提示回工作台查其余。生成成功不表示飞书已送达，送达状态看发件箱。

## 收件箱来源与项目归类

在收件箱点「多选」，可按当前筛选逐条选择个人收件，或全选当前已显示的条目。每批最多 100 条。可将未归档项一起归档，也可将已归档项一起恢复。批量归档后，点「撤销本次归档」可恢复刚归档的这一批。若其中一条之后被修改，整批撤销会停止，可核对后重新选择需要恢复的收件。原分拣结论和关联待办会保留。

个人采集分别读取私聊、群 @我和普通搜索并去重；首次从最近24小时起读，之后按持久水位分页续读，每批每路一页。覆盖范围以实际完整性状态为准，不把首批结果冒充完整历史同步。收件箱支持私聊、群 @我、群聊、Agent 协作和未识别来源的快捷筛选，并可组合处理阶段、项目、分拣建议和关键词。私聊与精确个人 @先交给后台整理，只有主 Agent 明确提出需要你回答的问题才进入待人决策；历史记录缺少来源时保持未识别，下次取得真实元数据后补齐，不根据会话名称或 ID 猜测。机器人自己被 @不等于个人账号被 @，机器人原有确认配置保持有效。

单条收件可在卡片或详情点「设置期限并转为待办」，也可点「转为待办」直接创建无期限待办。在多选栏点「转为待办」可统一设置这批收件的期限。支持今天全天、一小时后、指定时间和无期限。每条收件各建一个待办，沿用原来的标题和所属项目，并归档原收件。全天待办在不同时区的日历里仍显示在所选日期。

打开消息详情，选择“归入项目”后保存。归类只更新消息所属项目，不标为已处理，也不创建待办或执行 AI。之后“转为待办”会继承项目。已归档消息可以归类且保持归档；已有待办的项目与目标不一致时，会提示先调整待办。主 Agent 也可通过 `inbox_list` 查询，再按当前用户要求调用 `inbox_assign_project`，使用消息当前版本归类。

在收件原文详情的“同一事项”中选择“关联到另一条收件”，用标题、来源或发言人查找上级收件。同一事项可以跨线程、来源和项目，每条收件保留自己的原文与处理状态。详情可打开上级和直接下级的原文，或解除当前收件与上级的关联。已经归档的关联仍可查看。个人飞书采集取得直接回复编号后，会在同账号、同会话的两条消息都已入箱时关联原消息。上级晚到也能补连。详情注明“飞书直接回复”或“主人手动关联”。选择“保留此上级”可固定自动关联，后续采集会保留该选择。解除后，后续同步若再次取得直接回复依据，仍可重新建立关联。出现版本冲突时，核对页面重新读取的关系后再操作。

主人在 Web 主对话或已配对的飞书主人私聊可问“这条收件关联了哪些消息”。助手用 `inbox_tree` 查实际关系，返回可见来源及工作台详情入口。群聊、项目对话和后台任务不能调用这个查询。

## CLI 与 Skill 消息来源插件

安装包包含可选 `dist/plugins/command-inbox/`，复制完整目录到 `<数据目录>/extensions/command-inbox/`，在清单的 `config` 配置 `name`、`command`、`args`、`collectEnabled`。默认命令为空、采集关闭。重启后沿用同一插件 SDK 加载；主 Agent 的 `command_inbox_collect` 工具只运行已配置的可执行文件与固定参数，不接受模型指定命令，不自动轮询。

企业 CLI、Skill 或 One Context 通过用户确认的只读适配器输出 JSON：`{"items":[{"thread":"稳定会话标识","last":"最新消息标识","title":"会话名称","text":"正文","origin":{"kind":"group","connector":"来源名称","chatName":"群名","mentionedMe":true}}]}`。也支持直接输出数组；个人 @必须由该适配器依据当前账号的真实标识判断。插件通过 `core.inbox.ingest` 写入独立来源命名空间，不能指定已处理状态、冒充别的插件或直接启动工作。本机没有 One Context 可执行文件；通用适配协议已本地验证，具体司内命令、登录及字段转换需按实际工具配置。

## 答复、交付验收与项目跟进

待办的“答复与验收”可开启关闭前需答复；可选择真实答复或出站回执。要求渠道送达时，只有实际 `sent` 回执满足条件，本地文字不代替送达。有完成标准的执行可关联交付，由用户明确接受或填写缺陷返工。验收后的执行证据发生变化时，重新读取「答复与验收」会显示证据已失效，并保留用户当时的决定。从执行机恢复的原生会话也可在此验收。会话编号或绑定执行者不匹配时，页面显示原因。返工时执行者会收到上轮执行编号与状态、本轮缺陷和当前有效的验收标准，按条目提供本轮核验的证据。督办和返工都会区分已经移除的要求与恢复生效的要求。返工使用新执行与独立轮次，默认最多 2 次，可通过 `/api/v1/task-closure/settings` 修改为 0–10；重复决定不重复派发，unknown 不自动返工。重开会使旧答复和旧验收失效，普通未开启约束的待办仍可手动完成。

项目“怎么跟进”中的每日简报开关独立于自动处理预设和离场通知开关；时区沿用全局简报配置，逾期提醒随项目简报合并。归档或关闭简报会使积压发送失效。自动处理选项真正写入项目策略：沿用全局清除项目覆盖，保守和平衡沿用现有预设，少打扰必须明确确认当前绑定的受信目录；更换工作区不携带旧目录权限。未配置跟进的旧项目继续沿用原全局简报，不主动创建项目日程。


## 工作决定、执行观察与连续采集

项目绑定到 Git 仓库根目录后，可在「发起执行」选择「从当前提交创建独立 Git 工作树」。选择「从同一提交并行执行」可一次发起 2 至 4 份相同任务，沿用所选执行者。对比页按组展示各份状态和结果。每次任务使用独立分支，目录位于项目旁的 `<项目名>-worktrees/<执行 ID>`。任务结束后保留分支与目录。需要让另一项任务使用当前文件时，在原执行详情选择「在此工作树发起执行」。原执行详情的「工作树关联执行」按时间列出后续任务，可查看各自的执行结果。新执行有独立记录，可返回原工作树；启动前执行机会核对分支和目录。飞书与 Web 助手也可按明确要求复用已有工作树。在执行详情选择「重命名工作树」可设置列表和对比页使用的显示名称。也可以按此名称询问助手。打开执行详情中的「查看工作树状态」，可以刷新当前分支、未提交文件和仍未进入来源目录 HEAD 的提交数。在执行详情点击「查看提交历史」，可切换全部提交和未进入来源目录的提交，每页 20 条。点击提交标题可查看 Git 作者、提交说明、变更类型及逐文件补丁。文件清单列出文本增删行数，二进制文件单独标记。Git 识别的重命名会同时展示原路径和新路径，两端均可浏览时可查看补丁。合并提交展示相对第一父提交的差异。清理目录后仍可查看保留分支。工作树状态显示 Git 识别的改名前后路径。可见文件每 250 项一页，翻页后仍可逐项打开。文件列表变化时从第一页重新读取。点击修改文件旁的按钮可分别查看暂存或未暂存差异，未跟踪文本文件可直接阅读。飞书和 Web 助手也可按执行记录查询。状态面板会列出在该目录及其子目录中排队、运行或结果未知的执行，可点击核对。执行已结束且没有占用时，可在 Web 状态面板确认清理干净的工作树目录。存在本地修改、未跟踪或忽略文件时会保留目录。清理后保留分支。若还需删除分支，在执行详情打开「查看保留分支」，核对提交和未合并数量后单独确认。分支已有新提交或正在其他工作树使用时无法删除。删除后仍可查看历史提交差异。也可以在飞书或 Web 对话中询问某次执行保留的分支还有几个提交未合并，或查询工作台确认删除分支的时间。复制的是起始提交中的文件，原目录的未提交修改不会带入。检出时跳过仓库自定义过滤程序，使用 Git LFS 的文件保留指针内容。

在「项目 → 执行」打开一条执行记录，用「选择对比执行」查看同一项目两次执行的任务、完成标准、结果与错误。执行机上报本次任务的原生用量时，对比卡显示输入与输出 Token，输入包含缓存。旧记录或缺少计数的任务显示「未上报」。任务在 Git 目录中启动和结束时，对比卡显示两端提交及目录内已提交文件数和增删行数。执行机在线时，可点击「查看文件差异」按这两个提交逐文件核对。删除的文件也可查看。在飞书或 Web 对话中可以请助手比较两次执行的具体改动，项目和事项助手只读取各自范围内的执行记录。共享目录可能包含他人提交，未提交改动另在项目代码侧栏查看。选择器优先列出同一待办的记录。可复制当前地址保留对比组合，也可在插件设置中停用「执行对比」。

记忆页的“工作决定”用于记录已确认的工作约定。可在全局或当前项目新增、编辑和撤回；每次变更保留来源和版本。它是共享事实账本，不会自动拼接私有聊天、生成知识或发送消息。主 Agent 和有权限的项目/事项 Agent 每轮读取当前决定，引用前核对版本；纠正或撤回后旧引用失败。版本冲突时草稿保留，核对最新决定后再保存。项目归档保留历史决定，停止新增和修改。

项目执行页显示执行者实际上报的最近阶段、工具名称和观察时间。“最后观察”不表示仍在执行，“未上报”不表示空闲；结果未知不自动重派。详情中的“等待你”来自真实开放交互卡和待批准事项。有逐题推荐时可在原卡链接旁查看推荐项及理由，答复仍在原卡提交。Web 或已配对的飞书主人私聊里，也可以问助手这次执行建议怎么选。督办按配置的等待时长检查运行中的提问，主人答卡后可到待办执行历史核对送达回执。旧执行机仍可提供合法原生结果；没有能力声明时不展示为支持结构化阶段。自定义执行者需声明其原生结果来源，屏幕文本不能宣称完成。

渠道的个人消息采集显示已完成水位、后续页和累计页数。首次从最近24小时起读，之后按持久水位续读并重叠5分钟去重。显式从某时刻重新开始时，私密断点可设置 `notBefore` 时间下限；后续重叠读取和回复证据都遵守该下限，避免清空后再次回填旧消息。清理历史前先暂停采集并备份 SQLite 与账号断点，清理完成后再恢复。三路分别覆盖私聊、群个人@及普通搜索；每批每路读一页，成功入箱后保存游标，全部路线耗尽后才更新完成水位。默认分页来源按真实消息标识独立入箱，避免同会话旧页覆盖其他请求；旧会话聚合条目保留。旧适配器无分页信息时明确显示缺少完整性证据。授权、开启采集和外发相互独立；停止后不会继续翻页，恢复仍校验原账号。


## 执行机启动器、凭证检查与旧终端

执行机支持 `--codex-command` / `--claude-command` 指定启动器，`--codex-config-dir` / `--claude-config-dir` 指定配置目录。对应环境变量为 `SUPER_MARIO_CODEX_COMMAND`、`SUPER_MARIO_CLAUDE_COMMAND`、`SUPER_MARIO_CODEX_CONFIG_DIR`、`SUPER_MARIO_CLAUDE_CONFIG_DIR`；未单独指定目录时沿用该进程的 `CODEX_HOME` / `CLAUDE_CONFIG_DIR`。显式目录同时作用于执行、诊断、历史发现和原生恢复；目录缺失不回退到另一账号的默认历史。命令和目录由这台执行机的启动配置决定，模型不能临时指定命令、参数或环境变量。

Agent→执行者与电脑→电脑详情，点击“检查安装与登录”后才执行固定的只读检查。安装、启动器、版本、本地凭证分别显示；状态未知时不当作已登录，也不自动登录或调用模型。启动和打开页面只注册能力，不主动检查凭证。

代理实例标识与机器标识、操作系统PID、终端编号、原生CLI线程ID分别使用。正常网络断线会继续观察本次代理启动创建的会话。代理重新启动后，旧绑定保留为历史；当前宿主未提供可靠daemon实例标识和原子恢复条件，不能根据相同终端编号或目录恢复读写。旧绑定无法核验时不打开画面或接管；已有原生任务结果仍可读取，需继续工作时从CLI会话申请原生恢复审批。此限制不代表原生恢复已经执行，也不自动创建新线程回退。

## 收到回复后停止等待提醒

先在待办保存“在等谁”和提醒时间，再点击该等待行的“跟踪回复”。选择已采集的原消息及同会话里实际出现过的回复人。可按内容、联系人或消息标识查找来源；缺少可验证消息时先配置只读来源，不会自动授权或发送消息。

系统只用同账号/来源、同会话、真实发送者ID及类型和直接回复关系匹配；昵称、同群、同话题和时间接近都不构成证据。命中后清除这轮等待提醒，保留截止时间和待办未完成状态。改变等待人、提醒时间、项目或完成状态会使旧轮失效。已排队的提醒按服务端轮次校验，重新设置相同时间也不会复活旧通知。事件写入失败时同一SQLite事务回滚，不留下“接口失败但已设置”的状态。

当前飞书CLI的话题格式可能只保留thread而缺少直接parent；这种消息不会自动停催。消息编辑、删除或缺少身份类型也不当作新回复。采集窗口可能不完整，未找到匹配不表示对方没有回复。

其他可信CLI/Skill连接器可在现有 `core.inbox.ingest` 批次中附加可选 `evidence`（SDK的`CollectedReplyEvidence[]`）；来源强制绑定插件和其sourceId命名空间，不能冒充飞书或其他账号。只需已有采集服务权限，不另建插件平台。普通命令收件箱的旧`items`格式保持兼容；具体司内命令仍需适配真实字段，未宣称One Context已实接。

打开工作台默认进入首页。「需要我」集中显示待决定和明确找你的消息；已转待办的来信由待办列表接手。「重要紧急」收录逾期或未来 24 小时到期的未完成待办，其余进入「重要不急」。顶部项目选择对首页各区生效。简报使用最近 24 小时的真实工作记录；项目总结单列未归项目。群聊动态只收录人数已核实且不超过 50 人的飞书群，按群显示条数与最近消息。

私聊已配对的全局机器人，发送 `/list` 或 `/对话` 查看会话清单，点选要继续聊的项目。只记得独立对话标题或其中一句话时，可发 `/list 关键词` 或 `/对话 关键词`。结果卡显示当前配对下匹配的未归档独立对话。可翻页，点「在这里聊」后再发消息继续。配置可访问的 `SUPER_MARIO_WEB_URL` 后，正文命中会附「查看原文」，点击可在已登录的 Web 工作台定位到该条发言。仅标题命中时可点「查看对话」打开记录。在未归档的 Web 详情中点「在飞书继续聊」，确认切换后回到机器人私聊发消息即可。浏览详情和切换目标都不会向飞书发送消息。发送 `/main` 或 `/主对话` 可把后续未引用的消息切回这个机器人的主会话。引用原项目的消息时仍会回到原项目。Web 主对话和机器人的主会话分别保存记录。

在 Web 打开「Agent → 更改模型 → 查看当前配置的模型清单」，或在已配对的全局机器人主会话私聊发送 `/modellist`。两个入口都读取服务端当前配置。内置目录列出已知型号，支持自定义型号的接入还会列出该接入最近成功使用的型号。查阅不会连接模型服务，也不会保存表单草稿。

要切换模型，在清单选择完整型号，点「应用到此会话」。Web 主会话和每个飞书机器人的主会话、独立对话各自保存选择。要从 Web 修改同一个机器人的选型，打开「Agent → 主 Agent 的飞书机器人」，点该机器人旁的「会话模型」。在 Web 的「独立对话记录」打开对应记录后，也可查看该对话的模型清单。在飞书当前对话中可直接发送 `/modelchange 完整型号`。下一条消息使用所选模型。接入地址、服务商或默认型号改变后，会话重新采用当前接入配置；只更换密钥会保留选型。收到结果未知的提示时可重新读清单核对。

若当前接入支持手动输入，可在 Web 的会话模型清单填写目录外的型号。应用到会话后，发送一条消息。实际调用成功后，同一接入的其他主会话也能从目录选择它。每个接入最多保留最近 8 个自定义型号。移除使用记录不改变会话已选型号。演示回复不计入使用记录。

启用「对话排队」后，Web 主对话和项目工作对话会标明每条输入正在排队还是正在处理。可以从输入框上方的「排队消息」查看等待顺序，或在原消息旁点「取消排队」。如果该条已经开始，工作台会提示状态变化；需要中断时再点「停止本轮」。展开「排队消息」，可调整仍在等待的消息顺序。调整只移动当前筛选范围内的消息；其他来源和其他范围的消息保留原位置。调整期间如果队列已变化，页面会重新读取当前顺序。点「取回编辑」可把等待中的原文、图片和文件放回原范围的输入框。已有草稿时可确认追加。核对修改后点发送才会产生新输入。取回后若浏览器断线，可在原消息旁点「恢复到草稿」。服务重启后，明确尚未开始的消息可从原答复手动重试。已经开始的轮次请核对实际执行回执。在 Web 对话中询问队列时，助手可通过对话状态工具核对当前范围仍在等待的条数和排在最前的一条。

在已配对的飞书主人私聊发送 `/stop`、`/停止` 或 `/停`，可请求停止当前目标的处理。要指明某一轮，引用那条私聊输入或点它的进度卡上的「停止本轮回复」。已结束的旧卡不会中断后来的消息。选中外部执行会话时，中断请求依照绑定的执行记录发送，可用 `/status` 核对后续状态。

在已配对的主人私聊发送 `/status` 或 `/状态` 查看当前会话。在全局机器人里引用已绑定项目的话题或消息时，按该消息所指的项目查询。过期或归档的项目会提示重新选择。状态卡只报告工作台保存的记录，执行结果和验收结论仍以对应回执为准。

在飞书私聊已配对的全局机器人，发送 `/help` 查看可用命令。单独发送 `/stauts` 等可识别的拼写错误时，机器人会提示重新发送正确命令。要讨论命令本身，可发送 `//status`，对话收到的正文是 `/status`。选中外部执行会话后，`/stauts` 和 `//status` 都按原文进入输入审批。发送 `/today`、`/今日` 或 `/今天` 可查看工作台时区内的今日简报。Web 在「Agent → 自动跟进 → 今日简报」读取同一份数据，也可在未选择项目的主对话中询问今天的工作概览。简报分别列出待决定、待处理收件、今日群提及、完成事项、失败原因、当前执行和日程。日历未授权时，其余栏目仍可查看。`/tasks` 直接打开任务进展，`/inbox` 打开收件箱。发送「工作台」、`/home` 或 `/dashboard`，可查看待决定事项、任务执行、收件和在线电脑。服务启动时可通过 `SUPER_MARIO_WEB_URL` 设置用户可访问的工作台地址。卡片导航不携带令牌；首次在飞书内置浏览器打开时，需要连接工作台。点击「发起执行」会打开表单，由用户确认提交。

个人群流读取消息前，先按用户身份核对群的通知偏好。飞书折叠群启用了免打扰，因此工作台仅对明确未免打扰的群查询消息。仅设置免打扰的普通群也会被跳过。无法确认群状态时，仅查询私聊。历史数据保留。


## 回看结果与逐件处理

对话页的「最近完成」显示近 24 小时的待办完成与执行结束记录，并遵循顶部项目范围。打开后分别显示两类数量；看过的记录仍保留，失败、取消和结果未知不作为完成记录。更早的记录在项目待办和执行列表查看。

在「项目 → 待办」打开「详情」，可以一起查看来源、等待对象、截止与提醒时间、当前决定和最近执行。点「添加决策」记录已定范围。用户在关联执行的问题卡上直接确认的答复，也能在这里查看来源。撤回决定后，后续派单会使用更新后的决定。

「交给 Agent」默认由主 Agent 选择执行者，也可以指定当前可用的执行器。委派会带上待办标题、备注、截止时间及等待事项。指定真实执行器时填写完成标准和预计分钟。交付时按验收条件核对来源、产物或测试结果。执行完成后，在「答复与验收」核对交付。

待办行的「执行历史」按实际执行次数展示轮次，默认读取最近 20 轮，可继续查看更早轮次。每轮显示执行状态、完成标准、结果和错误。返工决定时间与派发回执更新时间分别显示。旧记录仅保留回执时间时，决定时间显示为未记录。返工派发结果未知时，可查看回执中记录的原因，例如派发调用未返回或回执核验未通过。旧记录缺少原因时显示「原因未记录」。有当前验收记录的轮次还会显示最新状态，例如已重开或验收证据已失效。长结果仅显示前 4000 字符，可打开原执行记录查看全文。待办改归其他项目后，历史只展示与当前项目匹配的执行。也可以在 Web 对话或已配对的飞书机器人中询问某项待办的返工原因和验收结果，项目及事项机器人按绑定范围查阅。

在要求返工的那一轮，可打开该次返工实际创建的执行。派发中或结果未知时，历史显示对应状态。查看历史不会发起新执行或验收。

「等你处理」中的「下一件」循环定位当前待处理卡片，支持从最小化状态展开。翻页保留同一版本卡片中的未发送回答；卡片处理后从导航列表移除。点击此入口只移动焦点，回答、批准和拒绝仍需在卡片上明确提交。


### 飞书卡片与按钮

普通只读查询和晚报无法创建或取消跟进、发送额外通知。早报可为重要会议安排会前跟进；已安排的主动跟进可按推送策略通知主人。

晚报单列仍记录为运行中、但在本次统计时段没有更新的执行，并显示最后更新时间。模型生成晚报时，按简报时区核对今天已结束的日程和明天最早的安排；日历无法查询时注明未核实。返回结果有下一页、超出展示上限或部分日程无法解析时，助手会收到列表不完整的标记。

机器人回复、执行结果、提醒与简报现在优先使用分区卡片。超出卡片大小限制时，在发送前选择原文；发送结果未知时不再改发文本，避免重复通知。原消息和线程回复关联不变，单连接和多机器人共用展示组件。

向已配对的全局机器人私聊发送「工作台」或 `/dashboard`，可查看日期、待决定摘要、执行与收件统计。卡片中的「任务进展」「收件箱」「工作台」可原地切换；每页最多 5 条，支持上一页、下一页和刷新。回调使用新订阅 `card.action.trigger`，需在应用的事件与回调中启用。手动接入的旧应用需要自行补上该订阅；自动接入向导已有该配置。

全局机器人主人私聊发送 `/new 第一句话` 可以开启独立对话。只发 `/new` 或「/新对话」时，下一条未引用的正文才开始新对话。使用 `/list` 可找回已有对话，`/main` 返回机器人的主会话。引用旧消息可沿原对话继续讨论，显式发送 `/new 正文` 则开启独立对话。Web「Agent → 主 Agent 的飞书机器人 → 独立对话记录」可按机器人回看这些发言。打开会话详情可以改名、还原默认标题、复制对话 ID 或归档。归档后可在「已归档」中查阅或恢复；向原对话发送新的用户消息也会恢复。飞书 `/list` 显示活动对话的当前名称。两处同时修改时，旧页面需重新核对最新版本。主人也可在独立对话中明确要求助手为本对话改名或归档。

独立对话详情的「删除对话」会要求再次确认。删除后，Web 历史、搜索和助手上下文追踪会移除该对话；旧飞书引用无法继续，当前选中的对话删除后回到主会话。进行中的工作或待决定事项会阻止删除，页面会说明原因。已发送的飞书消息、独立业务记录和已整理的知识仍会保留。仅需暂时收起对话时可用「归档」。

在未归档的独立对话列表可手动调整顺序，也可恢复按最近发言排列。已排过的对话在前，新对话按最近发言顺序接在后面。归档本身会保留位置。若在归档期间重新保存顺序，已排过的归档对话会保留在可见对话之后。飞书 `/list` 和主助手读取的独立对话清单也采用已保存的顺序。

在独立对话详情可添加、移除或清空标签，每段对话最多 10 个标签，每个最多 32 个字符。列表按标签精确筛选，可与关键词及归档分类组合。打开「管理标签筛选」可指定显示哪些标签以及排列顺序，也可恢复自动显示已使用标签。筛选设置按当前配对的机器人保存。

在独立对话记录中输入标题或发言中的连续文字，可分别查未归档和已归档的会话。选择正文摘录会定位到原发言，可向前、向后加载上下文。启用对话历史搜索插件后，也可在 Web 主对话指定机器人，或在该机器人的飞书主人主会话中用自然语言查找。

已配对的主人在全局机器人私聊发送 `/home` 或「工作台」，可让机器人发送并置顶一张工作台卡片。再次召回工作台会发送新卡；机器人拿到新卡置顶回执后再处理原工作台卡。工作台内容变化后会刷新。已有应用可在飞书开放平台开通 `im:message.pins:write_only`（添加和取消 Pin）和 `im:message:recall`（撤回原卡），再发布应用版本。Web「Agent → 主 Agent 的飞书机器人」显示最近一次置顶回执。若飞书仅接受文本，或置顶结果未确认，可到 Web 查看事项。

卡片导航只允许当前配对主人在原私聊使用。普通导航授权有效期为 24 小时，当前置顶工作台会自动续期。重新配对、改绑或停用会使旧入口失效；转发到其他会话不可使用。没有可靠主人身份时，仅提供 Web 导航。Web 地址来自 `SUPER_MARIO_WEB_URL`；未配置有效地址时隐藏 Web 按钮，不生成带令牌的卡片链接。

导航和刷新只读状态。批准、拒绝、发送与验收仍在 Web 打开当前事项后确认，不在旧卡片上直接执行。飞书客户端真实展示和按钮回调仍需在对应租户实测；本地接口替身验证不能代替真实租户验收。

### 对话进度与现场终端

真实模型对话会显示正在分析、工具调用和回复生成阶段。飞书机器人将公开进度与回复更新到同一张卡片；更新失败时保留最终正文通道，长回复另行交付完整正文。只展示阶段、工具名称和公开回复，不转发原始推理或工具参数。原生思考气泡尚未接入。

在工作台或项目「执行」区点击「多屏现场」，终端墙在当前页面打开，沿用工作台登录状态。从项目进入时，列表按项目目录筛选。选择执行机和 Herdr 会话后，多屏只读显示各窗格。切到单屏并点击接管即可输入。切到完整界面可直接操作该会话的 Herdr 客户端，执行机需要 Linux PTY 和 Python 3。关闭现场会释放浏览器连接，窗格里的进程继续运行。

执行机默认连接本机 Herdr。可以用 `HERDR_SOCKET_PATH` 指定 socket，或用 `HERDR_SESSION` 指定命名会话。会话中的窗格标识只在该会话内有效。

现场终端使用独立深色调色板和最低文字对比度。完整画面同步绘制，固定尺寸不会反复重建画布。顶部「一键分析完整对话」按原生会话 ID 从头读取日志固定快照，并将全部公开对话与工具记录分段归纳后汇总，结果显示在终端上方。结果注明快照时间、读取字节数和记录数，区分已完成证据、进行中事项与风险。没有可靠会话 ID 时先选择会话；缺失、损坏、分页不连续或模型失败时明确报错，不用最近输出代替完整记录。原始推理、系统指令和独立子会话不纳入当前会话分析。

已配对的主机器人可以在「渠道 → 手动接入」开启「主机器人直接处理已配对主人的私聊」。新私聊仍写入收件箱，随后自动交给主 Agent。快速完成时直接回答案；处理超过约五秒时更新进度卡，派发工具开始时可提前显示。群消息和外部动作沿用各自的确认设置。旧待确认消息需要单独处理。
主机器人在已配对主人的私聊发送普通回复或提醒时，「工作台」和「收件箱」在飞书内更新当前卡片。旧消息保留发送时的按钮，可在私聊发送「工作台」打开新卡。

已配对主人私聊主机器人时，发送「工作台」，首页优先展示最近有公开答复的三个项目，可先看绑定电脑和最近答复摘要，也可在「全部项目」翻页。点项目的「在这里聊」，接下来输入的消息会进入该项目在 Web 工作台中的工作 Agent 对话。点「切回主 Agent」恢复默认对话。引用选定项目的卡片或在该话题中继续提问时，优先使用卡片绑定。选择有效期沿用卡片的 24 小时授权；项目归档后需重新选择。项目工作 Agent 与执行机上独立运行的原生 CLI 会话分别管理。

在已配对的全局机器人私聊发送 `/start 检查构建结果` 或 `/开工`，会打开执行表单。选择执行者和项目，核对目录与目标，再点「发起执行」。交互模式可继续对话。一次性真实任务还需填写验收标准和预计分钟数。Web 的「执行」可按相同编号查到这次提交。如果启动结果未知，先查看原执行记录和电脑回执。

私聊已配对的全局机器人，发送 `/agents` 或 `/agent 关键词` 可查执行会话。可按电脑、执行者、项目、目录或任务内容筛选。清单优先显示有待处理交互的会话，其次是运行、排队及执行结束但关联待办尚未完成的记录。点选运行中的交互会话后，下一条普通消息会生成输入审批，可在 Web 审批中心核对正文后发送。发送 `/status` 可核对已选执行的目标、验收条件、最近一次公开进展及仍待决定的事项。卡片最多列出最近 5 项；配置工作台地址后可点「查看执行」打开 Web 详情，在时间线的「等待你」处刷新完整清单。发送 `/main` 切回机器人主会话。

主人私聊工作台卡片可点「查看 CLI 会话」，也可发送「CLI 会话」或 `/sessions`。机器人读取执行机的原生会话元数据，在当前私聊发送可翻页的只读快照，按日志更新时间最多展示 100 条。电脑离线、发现范围截断会在卡片标明。分页使用同一份快照，查看不会启动或恢复 CLI。

会话标有「申请恢复」时，主人可在飞书卡片填写继续工作的目标、验收条件和预计分钟，并确认原终端任务已停止。机器人重新核验会话后，在私聊回传申请编号。到 Web 工作台核对并批准后，执行机才会启动恢复任务。

主机器人工作台显示「待回答的问题」时，点开列表，再点「回答这个问题」。在卡片内查看原问题、填写并发送回答，机器人会回报是否已送达。已经处理、过期或转给其他处理人的问题会提示重新查看。权限、计划和验收仍在各自的决策入口处理。
当提问来自当前主人私聊，机器人可直接把回答表单回复到原消息。提交后，关联执行收到输入，或由发问的 Agent 在原会话继续处理。


主 Agent 默认后台整理个人收件。逻辑工作目录固定为 `<数据目录>/pi/workspace`，可在收件箱「后台状态与工作目录」核对。后台沿用主模型与工作原则，分析会话互相隔离且不配置工具；Codex CLI 传输层仍使用隔离临时目录。项目代码目录保留在项目绑定中，不作为后台模型的任意文件访问入口。

会话卡中的「归组事项」按主题列出原文。可以搜索事项标题或摘要，展开原文核对来源，单独标记完成或重开。标记完成会保留原文，也会保留同一会话其他事项的状态。

后台整理会把普通追问归回已有事项并重开。致谢或收悉可以记在原事项里并保持完成。若新工作承接了近期已处理事项，会显示前项供核对。分级理由和紧急标记以这一事项的原文为依据。主人在 Web 主对话或配对的飞书私聊中也可以按原消息查询所属事项。没有整理结果时，仍可查看原始消息。

模型未配置、分析失败或返回无效归组时，已启用的飞书来源插件可按直接回复和话题编号归组。私聊中仍未找到归属的新消息可接到最近两小时有消息活动的候选事项，群聊缺少结构依据时分别保留。演示模式也使用此路径。新事项标为连接器规则归组，保留原文，没有模型摘要。如果规则把原文追加到已有模型事项，页面会注明该摘要来自前一次分析。此步骤只整理收件；原始消息、事项来源和待办可分别核对。

后台在新消息到达、主人回复或已关联任务的真实状态变化后重新分析。相同输入不会循环调用模型。默认每三秒检查一次，短暂合批，一次整理一个会话；私聊优先，群聊必须具有已核验的发言人身份和不超过五十人的成员数。归档项目不自动处理。模型失败时原文保留，自动重试最多三次，间隔至少五分钟；可手动重试，也可暂停整个自动整理。

只有缺少主人才能提供的关键信息时，合并卡片显示「待你回复」。在卡片填写回复后，后台会携带该答案继续处理。整理只自动创建或补充本地待办，不覆盖人工备注，不把执行结束当作验收完成；外部回复、执行和业务审批仍沿用已有权限。旧版系统简报中尚未发送且精确匹配的待审批记录会撤销，不补发历史简报，不改变结果未知或业务审批。
